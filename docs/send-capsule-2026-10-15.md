# 发送：消息变成一颗胶囊飞进对话（2026-10-15）

> 2026-10-17 更新：胶囊的外观和落地方式已再改一遍，见 `docs/send-lift-2026-10-17.md`：药丸的紫色描边和辉光、触地压扁与光环、“药丸 → 同材质气泡圆角 → 气泡底色”三段材质、折行消息 68 ms 的版式互补淡化，都被一个“离开页面的高度”取代（阴影、尺寸、材质、描边只是它的函数）。落点预测与跟踪、版式交接要围住两种版式、保留真实条目、首页淡出、引导、减少动态这些机制仍然有效；本文第二、三节里“触地压扁、光环、`settle`/`ring` 层”的描述已被取代。

起因：用户说“现在已经有基础动画了，但是不灵动不具有胶囊感，我想要设计流畅简洁的高级动画，一切按你的审美随意设计”。
这是 2026-10-14 那版飞行（`docs/send-flight-2026-10-14.md`）的重做：落点预测、保留真实条目、首页淡出、补充要求、减少动态这些机制都没动，换掉的是**飞的是什么、怎么飞**。
实现是 `src/sendFlightMotion.ts`（物理，纯函数，不碰页面）+ `src/sendFlight.ts`（把它画出来）+ `src/components/send-flight.css`（样子）。

## 一、旧版为什么不灵动、没有胶囊感（逐帧量到的）

- 飞的是**一行字**；气泡底板是 120 ms 以后才淡淡长出来的（深色下气泡只是 5.5% 的白，`rgba(224,230,242,.055)`），落地前的大半程是“字在滑、矩形在后面追”，看不出一个整体。
- 起步偏懒：纵向 `cubic-bezier(.28,0,.2,1)`，起始速度只有平均的 0.18 倍，峰值在三分之一处。
- 唯一的“弹”是底板 0.9→1 的缩放，文字完全是刚体平移。
- “边缘亮一下”在整段飞行结束（618 ms）之后才发生，和落地不是一件事。

## 二、设计：胶囊发射

回车的瞬间，文字被一颗**胶囊**裹住——胶囊用的是**输入框自己的材质**（面板色、发丝边），像从输入框里切下来的一块；它带着弹簧感离岸，沿一条先爬升后滑入的弧线飞向落点，途中被加速度拉长、倾斜一点；触地时被压扁一下、泛一圈光，再**松弛成对话里安静的气泡**。三条原则：

1. **文字永远是刚体。** 只平移（和起步时一次对齐字号的缩放）、跟着胶囊微倾；字形从不被挤压。弹性只在壳上。
2. **一个物体、一条时间线。** 胶囊出现在字的周围就不再换物体：同一块材质依次是药丸 → 同材质的气泡圆角 → 气泡自己的底色。
3. **简洁。** 没有粒子、没有拖尾、没有第二个动效抢戏：一圈弹簧、一次挤压、一圈光，各自只出现一次。

### 看到的（单行消息，约 520 px 的路程）

| 时间 | 发生了什么 |
| --- | --- |
| 0 | 第一帧就是输入框：字在原位（与输入框的墨迹框重合），胶囊在这一帧开始从零长出（48 ms，皮肤宽度不变、高度从 0.9 鼓到 1，轻微过冲） |
| 0–100 | 两条弹簧起跳，峰值速度 ~2450 px/s 出现在约 90 ms；壳被加速度拉长（≤6%）、整体向上微倾（≤1.5°）；阴影斜拖在后面，胶囊“离开了页面” |
| 100–390 | 竖向先到位、横向后到位，路径是一道弧（先爬升，再向右滑入）；这一段 95% 的路程已经走完 |
| 395（触地） | 第一次到达落点：壳被压扁（高度 −7.5%，≤4.5 px，宽度 +3.7%）并回弹一次，一圈柔光从气泡边缘涌出 |
| 触地后 ~170 | 药丸 → 同材质的气泡圆角（几何先变）→ 气泡自己的底色（材质后变）；阴影收回；思考中的那一行此时才出现 |
| 553 | 交接给真实条目，像素差与上一版相同（均值 0.7–1.0/765，位置差 ≤0.01 px） |

时间随路程缩放：触地 `290 + 0.2 × 距离` ms（夹在 320–470），整段 = 触地 × 1.4（这条路程 395 / 553 ms）；短路程（126 px）320/448 ms，长路程（847 px）459/643 ms。

### 材质（`send-flight.css`，亮暗各一套）

- **皮肤**：`color-mix(--accent 7%, --loom-workspace-panel)`（亮色 5%）+ 1 px 发丝边（30% 强调色混入面板线色）+ 顶部一条高光。暗色下它几乎就是输入框的颜色，所以起飞前后看起来是“同一块东西”；亮色下是白色加薄紫边。
- **光晕**（阴影 + 一点强调色）和**光环**（触地的光）是椭圆径向渐变，不是模糊的 `box-shadow`：比胶囊大一圈，露出来的是渐变的软尾；亮色下这是一块真正的浮起的接触阴影。
- **气泡自己的底色**用 `cloneNode` 的真实气泡，所以最后一帧就是真气泡。

## 三、怎么做的

### `sendFlightMotion.ts`：把时间线算成数字（每 8 ms 一帧，WAAPI 关键帧）

`capsuleMotion({ dx, dy, width, height })` 返回九个部件的关键帧：

- **路径**：横、竖两条欠阻尼弹簧，竖向 0.82×触地时间、横向 1.22×，路径因此弯成弧；阻尼比由“最多过冲 5 px”反解（ζ≈0.83–0.9）；最后 30% 的时间用余弦包络把残余振荡收到恰好 0 且速度为 0（否则弹簧尾巴会在终点前停住）。
- **壳的弹性**：应变 e = 路径加速度经过一个 7 Hz、ζ=0.5 的二阶弹簧的响应（加速→拉长，刹车→略压）；触地是对同一个弹簧的一次脉冲（沿高度压扁 q、宽度 +q/2）；矩阵 `diag((1+e)(1+q/2), (1−q)/√(1+e))`。拉长是沿**药丸自己的长度方向**（水平），不是沿行进方向——沿对角线拉会让药丸相对文字错切成平行四边形（第一版就是，帧里像一根香蕉）；e ≤6% 且总共不超过 14 px（宽的胶囊按比例更少），几乎竖直的路程再减半。长路程形变大，短路程几乎不形变（`reach = √(距离/360)`）。
- **倾斜**：速度经过一个 4.5 Hz 临界阻尼弹簧，所以是“压进爬升”而不是突然开启；宽的胶囊倾得更少（同样的角度两端摆得更远），几乎竖直的路程没有可倾的方向，不倾。药丸和文字作为一个刚体一起转（文字在 1.5° 以内转动时边缘比不转略软，这是为“活”付的小代价；转动在落地前归零，交接处是精确的单位变换）。
- **皮肤 / 气泡圆角 / 底色**的不透明度、**光晕**（随速度后拖、随高度抬起）、**光环**（触地涌出并扩散）。
- 触地之后的所有安排按“剩余时间”的份额排，所以短路程也不会有东西落在整段结束之后。

### `sendFlight.ts`：DOM

```
ghost（路径 translate、倾斜 rotate；left/top 每帧跟着页面的落点）
 ├ shell（起始形状：围着输入框的字，再长成气泡）
 │   └ membrane（弹性：矩阵形变，围绕胶囊自己的中心）
 │       ├ halo   光晕
 │       ├ skin   药丸（输入框材质）
 │       ├ settle 同材质、气泡自己的圆角
 │       ├ card   真实气泡的克隆（无字）：气泡自己的底色
 │       └ ring   触地的光
 └ text    真实气泡的克隆（无底）：文字，刚体
```

- **起始形状**：一行的消息 = 气泡按输入框字号放大（和文字同一个缩放、同一个原点）；重新折行的消息（字符更多、列表等，**这是真实使用里最常见的情形**：输入框 822 px 宽、气泡最宽 610 px）= 输入框里那块文字的包围盒加上气泡的内边距，然后和文字换排版**同一时刻**长成气泡的形状（缩放 + 位移，`EASE_RESHAPE`）。输入框的字与气泡的字用互补的同一条曲线交接（两层不透明度加起来是 1，不再是两道缓动各算各的，中间不再发亮重影）。
- **交接顺序**：不透明的药丸比同材质的“气泡圆角”层小，所以后者在上面淡入时药丸被盖住，等它完整了才撤药丸，再让它让位给气泡自己的半透明底色。直接把两层不透明的东西交叉淡化会在中间凹下去（`1 − a + a²`），这就是为什么不是一层淡出一层淡入。
- 所有动的东西仍然只有 `translate / rotate / scale / transform(矩阵) / opacity`，在合成器上；每帧主线程只写幽灵自己的 `left/top`。

## 四、量到的

- 交接：幽灵最后一帧对真实气泡，位置差 ≤0.01 px；像素差均值 0.72（深）/0.98（浅），与上一版同级。
- 每个部件起点、终点都在静止：路径起点 = 输入框，终点 = 条目；壳矩阵、倾斜 = 单位；皮肤/光晕/光环 = 0，气泡自己的底色 = 1（单元测试对 7 种路程逐一验证）。
- 首帧位移：16 ms 时已动（0.5 px 以上）且没有猛冲（≤ 2.5% 路程 + 8 px）；峰值速度 630–3600 px/s（随路程），出现在 70–110 ms；过冲 ≤5 px。
- 稳态（第二次发送）的渲染开销与旧版相同（Chrome trace：渲染主线程 BeginMainFrame、GPU 线程忙碌时间同级）。
- **第一次发送有一次性的 GPU 开销**：全新的 headless 配置下，ANGLE 工作线程在发送那一秒里多做 ~250 ms（旧版 ~190，新版 ~430，逐层关掉某一个并不能明显降低，要全部去掉才回到旧版）；第二次发送就没有了。这是着色器程序第一次被用到时的编译，真实应用有持久的 GPU 着色器缓存，所以预期只在装上这次更新后的第一次发送出现一次。试过在空闲时先放一颗看不见的胶囊预热，没有降低这个数，所以没做；如果以后发现用户第一次发送有掉帧，先看这里。

## 五、测试和工具

- `scripts/tests/send-flight.test.mjs`（静态，CI 跑；现在 11 个）：新增物理层的单元测试——起止静止、不猛冲、触地时间在 320–470 ms、过冲有上限（用常数，不用被测模块自己的参数）、每个轴只靠近不回头、形变和倾斜有界且逐帧平滑、药丸只在上层圆角完整时才撤、弹簧本身是阻尼的；动的属性只能是 translate/rotate/scale/transform/opacity。改坏 11 处各自会红。
- `scripts/tests/send-flight-browser.mjs`（真实页面，9 组场景）：壳的层次、文字在任何时刻都在药丸里面（且留出内边距，而不仅仅是被盖住）、重新折行的消息在输入框排版和气泡排版里都被围着、终点只剩气泡自己的底色。改坏 5 处各自会红。
- `scripts/motion-lab/flight-film.mjs`：现在把页面上**所有**动画一起暂停、一起跳到同一时刻（旧版只冻结飞行层，输入框、占位符、思考行按真实时钟走，帧里的输入框是错的）；新增 `--scene onion`（每 N ms 一帧叠成一张图，看路径、间距、倾斜）、`--from card|steer`（从启动卡 / 任务进行中发送）、`--cols`。`flight-trace.mjs` 新增 `--css`（注入规则，量“去掉光晕会怎样”）并打印 `arrive`。

## 六、没做、可以做

- 输入框一侧的反应（退一下、顶边亮一下）：胶囊已经是“从输入框里出来”，再给输入框加戏会让每次发送都多一个动效，没做。
- 启动卡 → 胶囊的形变：卡片圆角与药丸不同，缩放会把圆角变成椭圆，需要第二层“起始皮肤”；现在启动卡发送是胶囊从卡片文字处长出来、首页在下面淡出。
- 有头 Chrome 抓真实合成帧：这台机器上窗口被节流（回车 200 ms 后才出第一个 launch，帧是旧的），抓不到可信的实时帧，所以验证用冻结 + 跳帧（它说的是动画“说了什么”，不是显示器“画了什么”）。
- 发送失败时飞回输入框（上一版就留着的）。

## 七、坑

- 在这个 shell 里用 `node -e` 写含反引号的文本，反引号会被 bash 当命令替换吃掉（这次把 README 改坏了一次，`git checkout` 恢复）：含反引号、反斜杠、`${}` 的内容一律用编辑工具写。
- 测试里的上限别引用被测模块自己的参数（`TUNING.overshootCap`）：把参数改大测试就跟着放行；用常数。
- 浏览器测试的“改坏再恢复”要等 Vite 看到文件变化（改完 sleep 3 s），而且别用 `env VAR=x cmd` 传环境变量（这里 `env` 会静默吞掉输出，退出码 0），用 `export`。
- `::placeholder` 的动画不在 `document.getAnimations()` 里：电影的第一批帧里输入框可能显示占位符，那是工具的假象。
- 机器忙的时候 `flight-trace` 的帧间隔毫无意义（出现过 200+ ms 的“卡顿”，换成旧版同样出现）；要比较就在另一个端口起一份提交版本（`git archive HEAD desktop-react` + `node_modules` 目录联接 + 单独的 `cacheDir`），交替运行。
