# 子代理完整对话跳转修复

## 原因与处理

- `thread/read` 会尝试恢复未被 App Server 顶层操作表登记的 RUNNING 会话。子代理由 AgentControl 执行，不在该表中；恢复操作可能等待其整轮执行锁，并把仍然有效的执行误当作中断。活动判断现在同时检查运行时生命周期令牌和 AgentControl 的未完成 Future，覆盖同步执行、后台执行及排队启动。
- 手机原先在读取完成前切换为聊天界面，失败提示却留在下面不可见的列表页；活动会话仍是父对话，看起来就像子代理跳到了主代理。现在读取成功后才切换，错误显示在当前页面，返回或新的导航会使旧跳转失效。
- 对话读取校验请求与响应的 ID。返回其他对话时拒绝应用，避免显示错误身份的数据。
- 线程记录携带图中持久化的父 ID 和代理角色；标题及线程管理包装层保留这些字段。子代理标题显示角色和短 ID，返回键回到原父对话及其建造/聊天模式。

## 验证

- Python：69 项通过，包括新的真实 MultiAgentRuntime 同步/后台运行读取、关闭后读取和排队所有权用例，以及孤儿恢复、子代理记录、导航、多代理恢复、标题、协议和项目回归。
- 手机浏览器：实际 Chrome 中通过两个不同子代理的独立消息、返回父对话、读取失败、错误 ID、重试、慢响应后退出、旧 Host、空列表及错误列表；320/390 像素无横向溢出，并检查生成截图。
- TypeScript、桌面构建、手机网页构建通过。
- 扩展 Node 检查：455 项通过，1 个测试文件失败。失败是已有未提交的 `portalLiquidFrame.ts` 改动缺少 `LENS_STRENGTH` 导出，与本修复无关；未修改该文件。

## 生效范围

这是源码修复；需部署包含修复的电脑 Host 和手机前端才会在已安装客户端生效。验证使用隔离测试会话与浏览器模拟桥，没有恢复、停止或改写用户的运行中研究任务，也没有重建其计划或长目标。
