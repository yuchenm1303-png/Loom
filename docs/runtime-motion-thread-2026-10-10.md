# 运行时任务流：织线重做与动效节奏统一（2026-10-10）

起因：用户反馈运行时很多动画“或多或少卡顿、互相冲突”，任务流条“排版读起来不方便、没有创意、和普通 agent 雷同”，授权整体重做。
这一轮先量化再改：用逐帧采样（`desktop-react/scripts/motion-lab`）在旧版上找到每一处跳变和叠加，再把任务流换成新结构，并让所有高度动效共用同一套规则。
范围是**运行时那条路径**：发送、思考、工具步骤、流式文字、审批、完成时的折叠。侧栏、设置页、模型面板等没有在这一轮动。

## 在旧版上测到的问题

数字都来自旧版（任务流还是 `task-flow-*` 的版本）在 `live-app.html` / `runtime-motion.html` 夹具里的逐帧采样。

1. **每新增一步，布局在一帧内被推下 35px**（live-app 的 code 场景里四次追加都是 35px），一个新阶段出现时一帧 +81px；而这一步的文字要 260–520ms 才淡完。动画是渐进的，位移不是。
2. **第二步到达时，第一行整体下跳 46px、图标右移 42px，一帧完成**：单步阶段没有标题，两步时才长出标题、导轨和缩进。
3. **同一个折叠/展开在三个文件里各写一遍**（`activity-flow.css`、`conversation-motion.css`、`task-lifecycle-motion.css`），时长有 175 / 190 / 240 / 250 / 260 / 270ms，曲线不同，还有 `!important` 互相覆盖；一边长一边缩时总高度会先鼓一下再回落。
4. **审批卡**：到达时下方内容一帧被推下 **120px**；条目和卡片各有一层入场动画，嵌套着同时淡入（`entry-approval > approval-card`，28 帧）；被处理后，App 把已处理的审批直接从列表滤掉，一帧消失。
5. **步骤状态靠改文字表达**（“正在运行”→“已运行”，换时态就重挂载并交叉淡入），状态点在所有已完成步骤上长得一样，不传达信息。
6. **“显示模型过程说明”开关**在第一条被收起的叙述出现时，从整个过程的最上方一帧插入，把整段内容下推 21px。
7. **带推理的短叙述会先打字、再整句消失**：用真实线格式的夹具实测，旧版里这句话上屏约 0.15–0.3 秒后被收回（`settleLiveText` 对带推理的条目整体不做暂存，等步骤结束被判为安静叙述再隐藏）。
8. **流式打字的节奏换挡**：积压按 72 / 180 / 480 / 1200 字分四档，每过一档速度约 +50%。
9. **夹具与真实线格式不一致**：`live-app.tsx` 给流式条目在 `item/started` 就带了 `phase`，而真实运行里 phase 要到响应结束才有，所以掩盖了这一类问题。

## 新结构：织线

一个阶段（连续的工具工作）是一根线，每一步是线上的一个节点（`WeaveFlow.tsx`、`weave.css`，类名前缀 `wv-`；步骤的数据与格式化在 `activityModel.ts`、`stepFormat.ts`、`liveWindow.ts`）。

- **动词不变，状态在节点上。** 一步的词（读取 / 运行 / 编辑 / 搜索……）从开始到结束不变，也没有时态；节点用自己的标记表达状态：进行中是强调色并带光晕、动词带光、右侧计时；完成是静灰；失败是红色 ✕、淡红底、结果标签和一行失败原因；未执行 / 已取消是灰色禁止标记；等待确认是琥珀沙漏。标签用文字再说一遍结果，不只靠颜色；每行还带一个只给读屏用的状态词。
- **行上能看的信息**：路径把目录弱化、文件名加粗，路径过长时先截目录；耗时（≥1 秒才显示）右对齐成一列；编辑显示 +/- 行数；运行中的命令在行下显示它最后一行输出（进度条式的 `\r` 覆盖取最终显示的那一段），结束后收起；失败原因取第一行有意义的输出（Python 的 `Traceback` 头取最后一行）。点开是完整命令加输出，编辑点开是带增删着色的 diff。
- **一个阶段结束就压成一行珠串**：每一步一颗圆点（失败红、未执行空心），后面是“运行 2 条命令 · 操作浏览器 3 次”和总耗时。点击展开，行按 28ms 依次出现。最新阶段和还在运行的阶段保持展开，读者的点击保留到该阶段再次运行。
- **长阶段只保留最新 6 步为行**，更早的折进同样的一行（浏览器会话一次点击一步，几十步不会把页面撑满）。折叠时旧行就地收起；只有能省下至少两行时才折。
- **完成时仍是整体收起**（行为未改）：只剩“任务过程”摘要行和最终回复。摘要行现在带着整段过程的珠串，一眼看出这次运行的形状、哪一步红了。
- 线在每个节点处断开，只露出节点之间一小段，读起来是串在线上的珠子；节点与思考胶囊的珠子在同一列、同一条中心线上。

## 动效规则（`weave.css` 是任务流唯一的样式 owner）

- **一条曲线、一个时长。** 所有“出现、收起、折叠、展开、折进更早的行”都是同一个高度动作：grid 轨道 0fr↔1fr，`cubic-bezier(.22,.74,.18,1)`，300ms。一边长一边缩时总和单调，不会鼓一下。
- **文字只淡入，变换只给没有文字的东西**（节点、珠子、光晕、线）。
- **一次性动效挂在“时刻”上**（`[data-born]`、`[data-settled]`、`[data-animate]`、`[data-opening]`），fill-mode 用 `backwards`，结束后不会把值钉在后面要跑的过渡上；不使用 `:has()`。
- 减少动态用具名元素列表关闭，不用通配选择器（那个列表会在每次样式重算时对每个元素匹配）。
- 旧的任务流样式分散在十个样式表里（`activity-flow`、`conversation-motion`、`workspace-surface-refinement`、`theme`、`typography-scale`、`icon-motion`、`task-lifecycle-motion`……里的 `task-flow-*`）已全部删除；`test_capsule_motion_contract.py` 断言整个 `src` 里不再出现 `task-flow-`。

## 其他修复

- **审批、子代理提示、错误行**：同一套“长进来”入场（高度一条曲线，文字淡入），去掉叠加的入场；审批被处理后由 `useLeavingItems` 保留 300ms，折叠消失，而不是一帧撤掉（桌面宠物的“等待审批”状态不把这张正在离开的卡算进去）。
- **模型过程说明开关**：第一次出现时按同一动作长出来，不再一帧把整段内容推下一行。
- **带推理的短叙述**：推理（正在思考）留在屏幕上，句子本身按其他短句同样的规则暂存到角色明确（2 秒保留期照旧，到点放行后不再收回）。实测（真实线格式夹具，新版 3 次）这句话 0 次上屏。
- **流式打字**：积压对应的速度改为连续函数（约 2 秒排空），60Hz 与 165Hz 下的基础节奏不变，只是不再有换挡。
- 夹具 `live-app.tsx` 改为真实线格式：流式条目没有 `phase`，完成时才写入。

## 验证

- 逐帧：第二步到达时第一行 0 跳变（旧版 46px / 42px）；追加一步、阶段折叠、审批长出与折叠、说明开关长出，最大单帧位移均 < 13px（旧版 35px / 81px / 120px / 21px 都是一帧）。这些由 `weave-flow-browser.mjs`、`approval-motion-browser.mjs` 在静止时采样断言。
- `conflicts.mjs`：任务流内没有嵌套同时淡入的元素，也没有同一属性上的两个动画；剩下的（思考胶囊、流式尾字、摘要行珠子）是各自一次性入场的有意叠加。
- 新增 / 重写的测试：`weave-flow-browser.mjs`、`approval-motion-browser.mjs`、`execution-sequence-browser.mjs`（重写）、`step-format.test.mjs`、`plan-update-notes.test.mjs`、`streaming-text.test.mjs`（连续节奏）、`execution-sequence.test.mjs`（带推理的暂存），以及 5 个 Python 契约测试的改写。每条新规则都做过突变检查：故意弄坏对应实现，测试随之变红。
- 复核中撤回了一个自己的改动：曾让“还没有字的 commentary”也画思考头，结果在工具调用还在流式输出参数时，“正在思考…”会和进行中的那一行同时出现；已撤回，并加了反向回归测试。
- 构建：`tsc --noEmit`、`vite build` 通过。仓库自带的性能守卫 `long-session-bench.mjs` 在新版上通过（长回合样式重算 late/early = 1.22×，阈值 3×）。新旧交替对比（`following`，各 6 轮，开发模式）噪声很大：任务时间新版 18.0–19.9s、旧版 12.4–20.5s，样式重算均值新版约 3.6s、旧版约 3.4s（高约 7%）。这个差距是否真实**没有定论**，需要在生产构建、更安静的机器上重测；旧版全量对比没有跑完（被中断）。

## 没做 / 已知

- 其他界面（侧栏、设置页、模型面板、输入框的非运行态）没有在这一轮审视。
- 没有在 Electron 真机和高刷新率显示器上测帧率；无头 Chrome 里主线程长帧很多（采样本身也有开销），不能当作性能结论。
- 流式 Markdown 的大块（代码块、表格、列表）出现时，布局高度仍是整块一次到位（视口跟随是缓动的，所以看起来是从下方滑上来，但布局本身没有过渡）。
- 思考胶囊、流式尾字等处“父子同时淡入”是旧设计的一次性入场，保留。
- 完成后展开的“任务过程”仍然完整展开所有阶段（读者主动打开，要的是细节），没有套用珠串折叠。
- 步骤的计时从工具调用创建时开始，经过审批等待的步骤会把等待时间算进去（数据里没有“开始执行”的时间戳）。
