## 本次修复与取舍

1. **杀 Host 的复合命令**：原先把同一行所有 PID 混在一起，出现任意无关 PID 就可能跳过按名保护。现在按语句分段，并让 `/IM`、按名过滤等不再被 PID 掩盖；也覆盖普通 `kill PID` / `kill -TERM PID`。仍然不承诺解析任意脚本、变量拼接或动态生成的命令。
2. **失败 spawn 的终止通知**：统一监听 `exit` 与 `close`，仅处理一次。保留已有 `error` 拒绝待处理请求逻辑和退避策略。新增真实不存在的可执行文件测试，验证无 exit 的路径；另测 exit/close 不重复调度。
3. **分线检查匹配**：要求真实 argv 的程序及完整参数一致；支持简单的 cmd `/c`、sh/bash `-c/-lc` 和带引号参数。复合 shell、重定向、变量展开不用于自动证明检查通过；让线补跑一次独立检查。代价是某些有效但复杂的命令会显示未验证，胜过把末尾 echo 的退出码误判为实验通过。程序按名称匹配仍不证明不同路径的解释器环境相同，也不证明检查脚本覆盖了科学结论；独立验收仍必要。

本次没有新增硬编码研究阶段、强制多代理或更多闸门。运行数据已有大量校验失败，再叠闸门不等于收敛。先修证据判断和恢复可靠性，再通过真实运行评估上下文阈值、资源配额和实验阶段策略。
