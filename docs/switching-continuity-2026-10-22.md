# 切换时的连续性：侧栏的三个按钮、羽毛笔、界面切换（2026-10-22）

起因：用户说"这个新建对话的羽毛笔图标动效仔细重新设计一下，现在切换时很多按钮变化还不连续，比如侧栏展开收起时这几个按钮，很多都是先消失再出现的，可以检查一下仔细设计切换效果"，并让上一轮（`docs/motion-feel-2026-10-21.md` 第八节）没做完的几项继续做。

## 一、看到了什么（真实 Electron 窗口逐帧录像）

先录下用户实际看到的画面，再动手。新工具 `desktop-react/scripts/motion-lab/film-electron.mjs`：在真实 Electron 窗口里用 `webContents.beginFrameSubscription` 抓合成器真正交出的每一帧（不放慢、不暂停），裁剪后排成一张图，每帧标上距离点击的毫秒数。

- **侧栏展开时，开关和羽毛笔先消失再出现。** 侧栏用 View Transition 截图，开关和羽毛笔各有自己的快照名，从头部的位置滑到卡片里。但在 Electron 里，这两个快照的"新"图像画出来是逐渐变淡的：开关和羽毛笔在动画中淡到看不见，~560ms 动画结束、真实元素露出来时才"啪"地出现。它们的计算样式一直是不透明度 1，所以原来那个只读计算样式的测试一直是绿的。
- **展开时标题被一条看不见的边裁掉。** 标题用 FLIP 从旧位置滑到新位置，但工作区已经在新的左边缘开始裁剪（`overflow: hidden`），卡片还没淡入，标题前半截就没了。
- **点击后 ~110ms 什么都不动**：截图要先把旧画面画出来再截。收起时开关的悬停底色在截图交接那一帧消失。
- **搜索按钮**收起时跟着卡片淡掉，头部没有它的位置。
- **切换会话时**，头部的上下文用量条在加载期间被置为空（消失），加载完再出现；右侧工具坞的计数点被强制归零（而且计数点是按"有没有数"渲染/卸载的，所以直接蹦出、直接消失）。
- **项目条**（输入框上方的"仓库 · PR / 文件"那一行）在项目会话和非项目会话之间一帧出现、一帧消失，整个对话跟着跳 32px。
- **设置第一次打开**：点击后 ~107–135ms 才出第一帧；第一帧是一整块不透明的深色画布、内容从 0 开始淡入，等于先给用户看一张空白页；点击的那个任务里整个应用（~1300 个元素）都在重算样式，因为外壳上切换了会继承的 `pointer-events` / `user-select`。
- **窄窗口 + 右侧面板开着时收起侧栏**：对话栏和输入框占满工作区，宽度变了，FLIP 对齐的是右边缘，于是左边缘一帧跳了 ~180px。
- **原生 `title` 提示**：系统的白框，约一秒后才出来。

## 二、改了什么

### 侧栏：一套按钮，不再截图

- 开关、搜索、羽毛笔变成**一个工具栏**（`SidebarControls.tsx` + `sidebar-controls.css`），由 App 渲染在窗口左上角、卡片和头部之上，永远不卸载。展开时它躺在卡片的第一行上（开关在行首，搜索和羽毛笔在行尾）；收起时卡片走掉，开关原地不动（还在静止的指针下面，悬停底色也还在），搜索和羽毛笔沿着同一条路滑到开关旁边，落在头部的起点上——头部只留一个 94px 的占位（`.thread-header-leading`）。
- 同一组 DOM 元素：没有"一个消失、另一个出现"，焦点不用交接，再点一次从当前位置掉头（CSS transition）。尾部的移动走面板时钟（390ms，`--loom-ease-move`），和被让开的标题、输入框同步；拖动侧栏边缘时它逐帧跟随（不加过渡）。
- **搜索收起后也在**：关着侧栏时点它，侧栏打开并直接落在搜索框里（Ctrl K 同理，搜索状态提到了 App）。
- 侧栏的开关**图标跟着方向倾斜**：开着时分隔线往里收（要关上），关着时往外推（要打开）。
- 删掉侧栏的 View Transition（`startViewTransition`、所有 `view-transition-name`、快照专用的样式和类型）：所有停靠面板都是活的。动画进行时工作区不裁剪（`body.loom-panel-motion .workspace { overflow: visible }`），标题和输入框从卡片下面滑出来，不再被看不见的边裁掉。
- 输入框的浮层把工作区抬到停靠面板之上时，工具栏也一起抬（`data-composer-popover` 也写到外壳上），否则头部的画布会盖住躺在它上面的按钮。

### 羽毛笔：一个想法一个状态

旧的是"悬停 100ms 后自动写一段带墨迹的签名"（每次经过都播 500ms）。新的：

- **悬停 / 键盘聚焦**：笔绕笔尖向纸面倾 6°（活泼弹簧，有一点过冲），笔羽（中间那根线）晚 45ms 跟上、多倾 2°——羽毛软的那一部分慢半拍。只是姿态，不自己播动画。
- **按下**：图形朝笔尖收（按下语言的 `--loom-press-glyph`）。
- **新建对话（点击、Enter、Ctrl N）= 一笔**：笔在 ~110ms 内向上一挑（-9°，略微离开纸面），落回时比原位多过 1.5° 再停稳（420ms）；同时笔羽先缩回根部、再从根部重新划出来——"写了一笔"。正在播的一笔不会被下一次点击从头重来。
- 去掉了只为旧动画存在的墨迹路径（`li-ink`）；减少动态时什么都不播。

### 切换会话：头部和工具坞不再闪

- 加载下一个会话期间，上下文用量条**保留上一次的读数并变暗**（`data-pending`，0.45），新会话的读数到了原地更新；工具坞的计数也保留（加载期间工具本来就是禁用变暗的）。（`App.tsx` 的 `useHeldWhile`）
- 用量条有了自己的出现过程：有读数时淡入，没有了（新对话）时带着最后的读数淡出，不再一帧消失。
- 工具坞的计数点**始终在按钮里**，只切换开 / 关（原本的样式里就写好了淡入和弹出，但它是被条件渲染的，所以从没播过）；淡出时还显示原来的数字。

### 项目条：折叠而不是跳

输入框上方的项目条在出现 / 消失时沿高度折叠（base 步，`inout`），文字一起淡入淡出；对话栏随之平滑地让出或收回 32px。

### 设置和个人页：第一帧更早、不再是空白

- 设置的**页面主体晚一帧画**（`usePaintedOnce`）：点击后的第一帧只画设置的框架（侧栏、空的主区），页面主体在下一帧渲染，此时主区正从 0 淡入，所以看不出它晚到。
- 被盖住的应用**在设置出现一帧之后才设为 `inert`**，设置开始离开时就恢复；去掉了外壳上会继承的 `pointer-events: none` / `user-select: none`（全应用样式重算挪出了点击那一帧）。`aria-hidden` 由 `inert` 代替。
- 设置的侧栏和个人页的内容**第一帧就读得清**（0.72，和所有按需打开的东西一样），不再先给一张空白画布；设置的主区仍按一个错开从 0 进来（它的主体晚到，藏在这段淡入里）。

### 窄窗口里的对话栏

侧栏收起时，如果一个元素变宽了（窄窗口里占满工作区的对话栏、输入框），FLIP 改为对齐**左边缘**：它从原来的位置滑过去，多出来的宽度从右边的停靠面板或工具栏下面露出来，而不是左边缘一帧跳一个侧栏宽。展开时仍对齐右边缘（左边那部分进到卡片下面）。

### 提示

新的全局提示（`GlobalTooltip.tsx` + `global-tooltip.css`）接管应用里所有的 `title`：

- 用工具坞名字提示的材质（深色 / 浅色两套），放在控件下方（下面放不下就放上面），夹在窗口内；名称后面的快捷键（"· Ctrl K"）用更淡的颜色分开。
- 纯图标的控件 420ms 后出现，带文字的 800ms；从一个控件移到下一个时立刻出现，并且滑过去（离开后等 90ms 给指针够到下一个）。
- 第一帧 0.72、fast 进、fast-out 出（浮层的语言）；按下后在指针离开前不再出现；滚动、按键、失焦都会收起。
- 悬停时控件的 `title` 暂存在 `data-loom-title` 里，系统提示就没有内容可显示，指针离开时还回去；键盘聚焦也显示同样的提示，但不动属性。工具坞自己的名字提示不受影响（`data-tooltip="none"` 也可以让某处保留系统提示）。

## 四、规矩和测试

1. 一个控件在两个地方出现时，用同一个元素在两处之间移动，不用两份各自出现 / 消失（侧栏工具栏）。
2. 不截图：所有停靠面板都是活的（`test_motion_feel_contract.py`、`test_panel_enter_motion_contract.py`）。
3. 加载新内容期间保留旧值并标记为待定，不清空再填回（用量条、工具坞计数）。
4. 会变成"有 / 没有"的东西有出现和离开过程（用量条、项目条、计数点）。
5. 按需打开的大页面先画框架、主体晚一帧；全应用的样式变化（`inert`）不放在点击那一帧。

测试：

- `sidebar-toolbar-motion-browser.mjs`（重写）：同一组元素、每个采样时刻都完全不透明、**像素级检查羽毛笔在移动途中确实画出来了**、开关不动、单调路径、掉头从当前位置开始、焦点保留、关着时的搜索和 Ctrl K / Ctrl N、浮层抬升、减少动态、窄窗口输入框的第一帧从原边缘开始。深浅两套主题、1440 / 760 两种宽度。
- `view-switch-continuity-browser.mjs`（新）：在 workspace-visual 夹具里挂起一次会话读取，验证用量条保留并变暗、计数不归零、读取完成后原地恢复、新对话时用量条走退出过程。（把 App 里的保留去掉，它会红。）
- `tooltip-browser.mjs`（新）：延迟、位置、属性暂存与归还、滑到下一个控件、按下后不再出现、工具坞例外、键盘聚焦。
- `quill-interaction-browser.mjs`、`icon-motion-browser.mjs` 第 8 块、`icon-motion.test.mjs`（羽毛笔的新交互）；`motion-language-browser.mjs`（没有任何快照；侧栏和其他停靠面板同一种语言；工具栏的尾部算"标记"）。
- 改了断言的旧测试：`window-rail-browser`、`right-tool-dock-browser`、`sidebar-navigation-browser`、`workspace-visual-browser`、`runtime-motion-browser`、三个 Python 面板契约。

## 五、没做 / 可以继续

- 归档视图和会话列表之间切换时，列表内容是一帧换掉的。
- 切换会话时"回到最新"按钮随对话一起卸载（这部分属于正在进行的"会话切换"工作，没有动）。
- 设置第一次打开时，框架本身的排版还要 ~20ms（第一次用到这些字体时的文字整形），第二次打开没有这笔。
- 窄窗口里展开侧栏时，对话栏的文字在第一帧就按新宽度重排（左边那部分进到卡片下面）。
