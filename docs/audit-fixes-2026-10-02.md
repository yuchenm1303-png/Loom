# Loom 审查问题修复（2026-10-02）

本次落实 [代码审查](code-audit-2026-10-02.md) 的 10 项问题，修复代码、补充回归测试并更新 CI。未部署生产服务。

| 审查项 | 完成的修复 |
| --- | --- |
| 1. 执行目标错误 | 网关以账号和设备 ID 路由，支持同时在线的多个 Host；浏览器明确绑定目标，缺少绑定或目标离线时拒绝执行。回应与通知也校验设备及原始请求归属。 |
| 2. 撤销后仍可使用连接 | 新增独立 relay credential，仅保存哈希并绑定原账号会话；网关每 30 秒复核，过期窗口内发送时也先复核。撤销、禁用、会话到期或验证故障会断连，普通 access token 轮换不会误断。 |
| 3. 并发重复建连 | 认证和建连共享同一 Promise；断连取消待建立连接，旧连接消息不再参与当前会话，心跳正确清理。 |
| 4. 设备在线状态错误 | 网关返回统一的 devices、selectedDeviceId、device 和 online 字段；刷新会向服务端重新查询。 |
| 5. CRLF 与回滚失真 | 读取和回滚保留 UTF-8 原始换行；结构化编辑与文本补丁覆盖 CRLF、混合行尾和末尾无换行。 |
| 6. 文件大小限制不一致 | 写入校验统一为 UTF-8 字节数，避免成功创建的文件无法被再次编辑。 |
| 7. 日志反复全量读取 | 正常日志追加仅检查末尾 1 字节，异常尾部按块扫描；增加近期事件 API。上下文校准和最新 usage 优先读近期事件，必要时回退完整历史。 |
| 8. 登录接口类型异常 | 非对象/无效 JSON 返回 400；不完整账号响应返回 502，服务端错误保持正确 HTTP 状态。 |
| 9. 续期竞态与故障处理 | 并发请求共享刷新结果，轮换后直接使用账号服务返回的身份；故障不触发轮换；退出会撤销最新刷新 token 并清理缓存。 |
| 10. 账号配置契约不一致 | 未配置时保留发布/开发默认地址；显式错误配置拒绝使用，不静默换服务。限制协议、拒绝 URL 内嵌凭据并修正 IPv6 loopback；同步相关测试。 |

同时为本地 Web UI 的跨域拒绝增加有界请求体排空，减少 Windows 连接重置导致客户端收不到 403 的情况。CI 与 Web Docker 构建使用 npm ci，CI 增加完整前端脚本、Electron 和 Web gateway 集成覆盖。README 明确供应商返回的 reasoning 文本保存行为。

新增行为回归测试覆盖双 Host 目标隔离、离线不回退、错误设备不能回应或推送通知、撤销后断连、慢客户端发送超时、请求并发上限、并发刷新、账户服务故障、字节级文件回滚和日志读取量。旧的“单账号唯一 Host”源码断言已由真实 WebSocket 和 Web bridge 测试替代。

## 部署与保留范围

需要先部署账号服务的新 `/v1/auth/relay-credential` 和 `/v1/auth/relay-me`，再部署带共享前端的 Web gateway。数据库启动时自动新增 relay_credentials 表及索引，保留原用户和会话。既有 Host 的握手仍使用原账号 access token；旧浏览器页面需要刷新以携带明确的目标设备。

网关仍需要单 worker/实例。多副本共享路由、历史 UI 虚拟化、大模块拆分和 import patch 重构属于后续维护工作；账号自助、统一备份、诊断中心及模型预算等功能建议也没有混入这次缺陷修复。
