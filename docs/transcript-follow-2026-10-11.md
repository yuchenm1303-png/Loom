# 对话视图跟随最新内容：点开步骤、按键、滚轮不再让跟随失效（2026-10-11）

起因：用户在一次运行中的任务（VNC 安装）里发现“生成的时候，消息没有自动往下顶、和最新位置同步”，觉得这一块有不少 bug。
这一轮先在能复现的地方复现，再改：把那次任务的 `events.jsonl` 转成回放（真实文字、工具、耗时，长间隔压到 5 秒），在真实 App 夹具里按用户的窗口尺寸（935×731 CSS px，150% 缩放）逐帧量“最新内容离可见底部多远”。
回放数据含用户的服务器信息，没有入库；通用的测量工具是 `desktop-react/scripts/motion-lab/follow.mjs`。

## 先排除的：正常运行中的跟随是好的

整段回放（两轮、共约 60 步、含决策卡点击、更新计划、浏览器与电脑操作）里，运行中最新内容落在视口外的帧只有零星的单帧、≤30px（新步骤出现的第一帧）。
“采样放在 rAF 里”会把这个数夸大：rAF 里读到的是控制器本帧修正之前的位置，读者根本看不到。`follow.mjs` 改在一帧画完之后的消息任务里采样。
所以问题不在“跟不上”，而在**跟随被意外关掉后没有任何东西把它打开**。

## 复现出来的三个问题

1. **点开任何一个步骤，跟随就永久关闭**（`onDisclosureClick` 对所有 `button[aria-expanded]` 一律脱离）。运行中的步骤本来就是可点的（点开看实时输出），点一下之后的 20 秒里任务继续往下做，视口始终停在原地，离最新位置的缺口涨到 356px；唯一的出路是一个压在正文上的小圆按钮。
2. **页面焦点在 body 时按 PageUp / 方向键，控制器完全不知道**：Chrome 照样滚动了对话，但上一次修复把键盘判定限定在“事件目标在滚动区内”，body 不在里面，于是下一次内容增长又把视图弹回底部，和用户的滚动对抗。
3. **滚轮向上只要触发就脱离**：对话本来滚不动（内容还没填满）时，随手一滚就关掉了跟随，之后内容超出视口也不再跟；滚轮落在命令输出框里（输出框自己在滚）时同样脱离。

另外上一次修复（591c0f66）改了控制器却没改两条契约测试，它们已经是红的；这次一并按新结构改好。

## 规则

离开“最新位置”必须是真的：

- **滚轮 / 触摸**：先看手势落点下面有没有自己能滚的框。没有 → 对话滚得动才脱离（内容放得下时不脱离）。有 → 不能凭输出框的 `scrollTop` 判断它有没有吃掉这一格：被动监听器下 Chrome 在合成线程已经把这一格滚了，实测事件到主线程时输出框的 `scrollTop` 已经是滚后的值（滚前 10、一格 −30，事件里读到 0），边界那一格会判错。这种情况只记下方向，**以随后对话自己真的往那个方向动了为准**。
- **键盘**：导航键只记录意图（文本输入框里的按键除外）；随后对话真的向上滚了（320ms 内）才脱离，不再看事件目标是谁。
- **滚动条拖动**：照旧。
- **点开步骤**：运行中的那一轮里的步骤 → 继续跟随（运行中的步骤正是读者要看着它干活的）。只在跟随会把刚点开的步骤标题顶出视口时（点的是视口上半部的行、展开又很高），读者是在读它：停在标题下 16px 处，按脱离处理、给回到最新的按钮。这个判断只在步骤自己的展开动画期间（420ms）做，之后就是普通的跟随，新步骤再多也不会因为“还开着一个步骤”而被冻住。已结束的轮次、决策卡等历史内容在原位展开 → 和以前一样脱离（它们的折叠不被追赶）。

## 数字（同一回放，改前 → 改后）

- 点一次运行中的步骤，20 秒后：缺口 356px、`following=false` → 缺口 0、`following=true`。
- 焦点在 body、PageUp：被弹回底部 → 脱离并停住。
- 内容放得下时滚轮向上：脱离且出现按钮 → 保持跟随。
- 整段回放的滞后清单（>4px 的帧）改前改后一致：运行中只有单帧 ≤30px；剩下的都在轮次完成的交接处。

## 没有改、但量到的

轮次完成的交接：回放里完成时有一次约 240ms 的主线程卡顿（整段过程重新挂载），随后视口在约 200ms 内缓动到新的底部，这几帧里最终回复最多有 440px 在视口下方，再接着是收起。
这是 `LIVE_SETTLE_WINDOW_MS` 那套“完成时可以缓动”的设计，不属于运行中的跟随，这一轮没有动；要动的话先从那 240ms 的重新挂载量起。

另有一个不属于这块的发现：失败命令的错误输出是乱码（Host 用 UTF-8 解码中文 Windows 控制台的 OEM 代码页输出，`app/agent_runtime/process_runtime.py`），已另开任务。

## 测试

- `scripts/tests/transcript-follow-browser.mjs`（真实 Chrome）新增：点开运行中的步骤后继续跟随且之后的增长被跟上；会被顶出视口的步骤停在标题处、有回去的按钮、之后的增长不会把读者带走；历史内容点开仍脱离且折叠不被追赶（零次控制器写入）；body 焦点的 PageUp 脱离并停住、End 回到最新；内容放得下时滚轮不脱离；输出框吃掉的滚轮不脱离、框滚到头后的下一次才脱离。
- 变异检查：分别把“运行中步骤继续跟随”“键盘按滚动为准”“输出框”“放得下时不脱离”“标题停留”弄坏，上面的测试都会变红（每次只改控制器里的一行、跑测试、还原）。
- `earlier-process-browser.mjs`：它用一个对话根本滚不动时的合成滚轮来“脱离”，现在改成先给对话一段临时的上方空间再滚，和读者真能做的手势一致。
- `tests/test_task_flow_motion_contract.py`：两条过期的契约改正，新增两条（手势与按键的判定、点开运行中步骤的规则）。
