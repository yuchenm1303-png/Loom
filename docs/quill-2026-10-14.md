# 新对话的羽毛笔：按参考图重画，动效整个重做（2026-10-14）

起因：用户先后三次回到侧栏“新对话”行的这支笔。
10-12 给了一张 Claude 桌面版里“写作 / 写大文件时左边那只橙色羽毛笔”的截图（`#d97757` 的描边，22×25 像素），说“把 Loom 里的羽毛笔改版成类似的，并精心设计交互动画”；
随后说“颜色还是紫色，形状要做成参考图那样，或者类似的饱满的”，又说“还是直接做成这个形状，交互动画也重新设计不用原来，简约精致灵动即可”；
这一次（10-14）再给同一张图，说“换成图 2，并设计交互动画”。上一版（`7a622d35`）是按这张图拟合的，只有约 81% 重合，放进应用里还是不像，所以这次形放在第一位，动效整个重来。

范围是 `Quill` 字形、它的动效、触发它的那一行（`NewConversationRow.tsx`）。颜色不变（侧栏强调色：深色 `#a99ff8`，浅色 `#6152cc`）；参考图的橙色是 Claude 的，不进 Loom。

## 形

### 它是什么

一条线，像人写的那样一笔：从笔尖出发，沿羽轴上去，绕过饱满的羽头，沿有缺口的右侧下来，再沿底边回到羽轴；然后在羽头里点一根斜的羽枝。所以字形只有两个元素：`li-outline`（53.6 个单位长）和 `li-barb`（7.5）。右侧偏下的那个“缺口”（先向外鼓出一个小尖，再向内收口）是这支笔最特别的地方，也是前几版都丢掉的地方。

24 格里中心线占 x 2.91–19.89、y 2.55–21.95，笔尖在 (2.91, 21.95)，羽枝从 (9.77, 12.96) 到 (15.26, 7.89)，共 8 段三次贝塞尔。线宽用调用处的 2.1（参考图的线宽 / 高是 0.113，对应 2.2；20px 下留 2.1 是为了羽头里的空隙不糊）。

### 怎么得到的（拟合，不是描）

参考图只有 22 像素宽，描摹会把锯齿也画进去。做法：

1. 由颜色反推每个像素的覆盖率 `(像素 − 背景)·(描边 − 背景) / |描边 − 背景|²`，背景 `#151515`，描边 `#d97757`，总墨量 163.2 px²。
2. 用 centripetal Catmull-Rom 的结点自由拟合覆盖率图（IoU .924），结点会抖；加弯曲能量（∫κ²ds，λ = 0.3）把抖动压掉。
3. 用 Schneider 算法把中心线拟成 7+1+1 段三次贝塞尔，再对控制点直接抛光（用“精确面积覆盖率”渲染器，6×6 采样）。
4. **用 Chrome 自己的光栅校准线宽和平移**：自己的渲染器比 Chrome 多出约 2.4% 的墨量，只按自己的渲染器拟合，线宽会偏粗。最后把底边的右端沿它自己的高度滑到羽轴中心线上（最近点会把底边拽高 0.7px，IoU 掉 1.7%）。
5. 缩放到中心线高 19.4，整体左移 0.6、下移 0.25（墨迹重心比外框中心偏右上 1.2 / 0.5 个单位，取一半）。

结果（Chrome 渲染 vs 参考图，同一像素尺度）：**IoU 0.895，墨量 163.2 / 163.2 px²**。不加弯曲惩罚能到 0.906，但右侧缺口下面会多出一个参考图里没有的小鼓包（拟合到了抗锯齿噪声），所以取了平滑的那一版，缺口本身保留。

在应用里看过：DPR 1、1.5、2，深色、浅色，20px，线宽 2.1；羽头里的空隙、缺口、羽枝都在。

## 动

设计原则沿用图标动效那一套（`icon-motion-2026-10-10.md`）：控件不动，图标回应；幅度约一个线宽；只有按下之外的动作才用弹簧。这支笔站在笔尖上，所以一切都绕笔尖。

| 状态 | 怎么动 |
| --- | --- |
| 悬停 / 聚焦（`--ic-on`） | 笔绕笔尖立直 5°（`.li-quill`，原点 (2.9, 21.95)），羽枝在它之上再抬 8°（`.li-barb`，原点是它的根），晚 45ms 出发，所以像被带起来的。进场用更活的弹簧（`--ic-spring-lively`，阻尼 .55，过冲 12%，笔多冲到 5.6°、羽枝到 9°），离开用平缓的 ease（260ms）。 |
| 按下 | 全局的缩到 .88 不变，但原点换成笔尖（`transform-origin: 12% 91.5%`）：不是缩向图标中心，而是像把笔按到纸上，羽头压向笔尖。 |
| 开始新对话（点击行、或 Ctrl+N） | 640ms（`--ic-t-write`）：线先收回笔尖成一个墨点，再从笔尖一笔写回整支羽毛，最后点出羽枝。 |

### 写（`li-write-*` / `li-flick-*`）

像一个落下去再弹起来的球：线向笔尖收回时加速（`cubic-bezier(.5, 0, .9, .55)`，0–90ms），在笔尖撞成一个墨点（14–16%），再快速离开笔尖、越写越慢（`cubic-bezier(.25, .45, .45, 1)`，16% 起到 86% 写完；这一段里完成度在 20 / 30 / 50 / 70 / 90% 的时间点是 .37 / .54 / .79 / .94 / .99，没有拖长的尾巴）。羽枝在线收回时一起消失，等整段时间走到 77%（这时线已写到约 .98）再从根上点出，147ms。两者都是 `stroke-dasharray` 的动画（`pathLength` 归一化），**只有 `backwards`，没有 `forwards`**：结束后动画的效果被撤掉，静止的样子就是字形本身，什么都没留下。

触发在行上：`NewConversationRow` 给按钮一个 `data-written`，值是 `odd` / `even` 轮流，两个值各对应一份内容相同的关键帧（`li-write-odd` / `li-write-even`）：第二次开始时动画名变了，才会在第一次没播完时重播。计数放在这一行自己里面，不放在 `Sidebar`（它会为了一个装饰重绘整张会话列表），行重新挂载时从静止开始；Ctrl+N 走 `ref` 上的 `write()`（`Sidebar` 的快捷键处理里调用），所以键盘开始一个对话时笔也会写。

### 减少动态

三处都守着：写的规则在 `@media (prefers-reduced-motion: no-preference)` 和 `:root:not([data-loom-reduced-motion="true"])` 两层之后；悬停姿态靠 `--ic-on`，减少动态下从不置位；`--ic-t-write` 和其余节奏变量一起坍缩。

### 没有做的

- 没有“羽片柔性”（羽头比羽轴晚一点弯）：需要把线拆成两段，写的时候两段的速度曲线接不上。
- 没有按下时的转动：笔松手时从按下的角度弹回悬停的角度，会在写的过程中让正在长出来的线跟着摆，像手抖。按下只缩。
- 不在悬停时写：写留给“开始了一个对话”这件事，悬停只是笔拿起来。
