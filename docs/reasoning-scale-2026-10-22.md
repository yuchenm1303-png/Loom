# 推理刻度尺（2026-10-22）

起因：用户截了模型卡里的推理控件（一根细轨，五个点，一个白色旋钮，下面是档位名和一行说明），说"仔细美化一下推理条吧，也不一定要是条，如果你有创意设计的话更好，交给你来处理"。
上一轮（`docs/composer-panels-2026-10-22.md`）把原来发光的蓝色珠子压成了一根安静的轨道；这一轮是让它**好看**，不是更安静。

## 一、现在是什么

一把刻度尺，不是一根条：

- 第一档到最后一档之间，每两档之间一串刻度，大约每 7px 一格（2 档 25 格、3 档 35、5 档 41、6 档 41、8 档 43）。**越往右越高**（6px → 24px，略带弧度），所以"高度"本身就是信息：越高，推理越深。每一档的那一格再长 3px。
- 选中那一档**左边**的刻度是强调色，右边是灰；一根白色指针（顶上一个圆点）立在当前档上，指针和刻度之间隔着一圈面板底色的发丝线。颜色只有一个意思：强调色 = 你当前的选择。
- 点刻度尺上任何位置（不只是字）选最近的一档；按住拖动，指针跟着手走，字和下面的说明跟着最近的一档变，松手才选中；悬停一档，它的刻度抬高一点、字亮一点、下面先读出它的说明；方向键 / Home / End 一档一档走。运行中锁住：刻度尺变淡，说明原因，按了也不动。
- 模型自己决定推理深度时（没有档位）：同样的刻度，全灰，没有指针，写着"自动"。
- 1 档到 8 档都画：单档、开 / 关、低中高、五档、六档、八档（八档时 "Extra high" 会被省略号截断，和以前一样）。

## 二、怎么做的，以及第一版为什么被推翻

**结构**（`ReasoningControl.tsx`，样式在 `composer-panels.css` 里的 `.cp-scale` 一组）：

- `.cp-ticks`：灰刻度，一次画好（`memo`），之后不再变。
- `.cp-lit`：一个窗口（`overflow: clip` + `overflow-clip-margin: 3px`，第一格和最后一格正好落在窗口边上），里面套一份强调色刻度 `.cp-lit-ticks`。窗口往一个方向移，里面的刻度往反方向移同样的距离，所以**刻度不动，只有窗口的边在刻度上扫过去**，亮的部分永远到指针为止。
- `.cp-slide` 带着 `.cp-needle`（画成最高，用 `scaleY` 调到当前档的高度）和 `.cp-pin`（指针头，`translateY`）。
- 这五个零件都只有一条 `transform` 过渡（`--loom-spring-settle`，320ms），位置是 React 写进去的行内 `transform`。`transform` 由合成器跑，主线程这 320ms 里基本是空的。

**第一版**用的是另一种做法：一个动画的自定义属性（`@property --cp-pos`，继承）带着指针的位置，每一格用 `calc` / `cos` / `color-mix` 去读它——点亮跟着指针扫过去，指针附近的刻度还会像波浪一样鼓起来。做出来很好看，但**每一帧都要重算样式**：

| 一次切档（0 → 4，320ms 弹簧，真实应用里量的） | 第一版 | 现在 |
| --- | --- | --- |
| 每帧重算样式的元素 | 184（控件本身只有 53） | 5 |
| 样式重算总耗时 | ~190 ms | ~12 ms（去掉字色和说明的两个 150ms 过渡后 ~3 ms） |
| 一次拖动（120 次 pointermove） | 样式 ~620 ms，主线程 ~1360 ms | 样式 ~90 ms，主线程 ~570 ms（开发模式的 React 渲染占大头） |
| 打开面板多出来的 | — | ~6 ms（~85 个静态元素） |

量出来的原因，不是猜的：

1. 一个**继承**的、在动的自定义属性，让它下面所有元素每帧重算样式（空页面里 54 个元素 ~0.6 ms/帧）。
2. 这个应用的全局样式表让每个被重算的元素都很贵（同样的探针放在应用里是空页面的 2.5 倍），而且**读了这个属性的元素每帧被重算 4 次**（Chrome trace 里 `UpdateLayoutTree` 的 `elementCount` 是 53 个元素 184，空页面里是 1 比 1），`<i>` 比 `<div>` 又贵一倍（全局的标签规则）。
3. `pointermove` 里的 `getBoundingClientRect()` 会强制同步重算一次样式，一次拖动白白多算一倍。

所以第一版 3 ms/帧——165Hz 的屏上一帧只有 6 ms。换成"刻度不动、窗口和指针只做 `transform`"之后，代价是**去掉了"指针附近的刻度鼓起来"的波浪**（刻度高度不能再随指针变：高度不是合成器能跑的属性）。如果以后要把它找回来，只有一条不经过样式重算的路：再画两层更高的刻度，放在一个带软边、随指针移动的窗口后面。现在的判断是不值得：指针 + 点亮 + 弹簧已经够活。

## 三、动效（和别处一样的规矩）

- 只有标记会动：指针、指针头和窗口走 320ms 的弹簧（flow 档），字只变色（150ms），说明换字时从 .72 淡入。
- 按住：指针头放大到 1.3（press 档，90ms，`scale`）；拖动时没有过渡，跟手；松手后弹簧落到那一档。
- 悬停：那一档的刻度抬高（`scaleY(1.12)`，fast 档）、字变亮。
- 减少动态：令牌折成 1ms / 过渡取消，指针直接到位。
- 没有光晕、彗星、爆裂、轨道环；唯一的"装饰"是指针四周一圈 1.5px 的面板底色，让它从刻度里分出来。

## 四、测试

- `tests/test_composer_panels_contract.py`：只有标记会动（五个零件各一条 `transform` 弹簧过渡）；强调色只出现在"点亮的刻度"（`.cp-lit ...`）；刻度尺没有光晕 / 彗星之类；指针是正文墨色；窗口会裁掉里面的亮刻度；**不再有任何动画的自定义属性**（没有 `@property`、没有 `--cp-pos`、过渡里没有尺寸和位置）；刻度只画一次（`memo`）；放置指针的行内 `transform`；拖动中不告诉 Host（`onPointerMove` 里没有 `commit`）；`setPointerCapture` 和 `event.detail === 0`。

## 五、顺手记下的

- `.cp-head` 已经是面板标题的类名，指针头第一次叫它，被标题的样式（48px 高的 flex）撑走了，指针头消失了——新加类名之前先 grep 整张样式表。
- `node -e "..."` 里放反引号和 `${}`，会被 bash 先执行掉；补丁脚本用 Write 工具写文件，或者直接用 Edit 改。
- Git Bash 只把**参数**里的 `/c/...` 转成 Windows 路径，`node -e` 的字符串里不会：`C:/...` 才能到处用。
- 1.5 倍缩放（用户的屏）下刻度的边缘有一点发虚：面板本身落在小数像素上，和以前的点一样，不是刻度的问题。
- 工具在 `C:/tmp/reasoning/tools`（镜像 `C:/tmp/reasoning/root`，Vite 5243）：`card.mjs`（截图）、`film.mjs`（暂停并逐帧定位的胶片）、`drive.mjs`（像人一样操作）、`ladders.mjs`（各种档数）、`zoom.mjs`（放大像素）、`cost.mjs` / `trace-*.mjs`（量代价和 Chrome trace）、`mutate-reasoning.mjs`。
