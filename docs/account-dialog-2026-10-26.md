# 登录与账号：一张卡片（2026-10-26）

起因：用户截了"Loom 账号"弹窗（已登录状态）说"帮我美化重构一下登录和账户相关界面ui和动效吧，简约高级即可"。

## 一、原来是什么样

账号弹窗（`AccountDialog.tsx` + `account-auth.css`，约 1300 行样式）是三层叠出来的：登录表单一层、已登录区块写在它上面一层、资料编辑器再写一层。

- **框套框**：图标方块、"登录 / 注册"分段标签、两个快捷登录按钮、带标签的输入框、等宽字体的"服务地址"框；编辑资料是卡片里套卡片，头像又一个框。
- **颜色各说各的**：深色主题主按钮是墨色，浅色主题是带紫色光晕的紫色按钮；编辑资料的"保存"是紫色渐变 + 光晕；裁剪头像的"使用这张头像"又是另一种紫色渐变。
- **坏掉的状态**："账号服务尚未配置"里的"重新检查"按钮没有样式，挤成两行的灰块。
- **样式串门**：内部类名 `.loom-account-form`、`.loom-account-switch` 和网页门户的同名类撞在一起；门户的样式表（`portal-base.css` 等）经 `WebAppGate` 也加载在桌面端，所以门户的 `.loom-account-form { margin-top: 23px }`、`input { height: 43px }` 会落到桌面弹窗上。
- **字号**：全是 rem（.62rem–1.12rem），不在产品的字号阶梯上；裁剪框里还有 10.5 / 11px 的字。
- **动效**：整卡淡入淡出（面板语言），里面的内容在状态之间直接跳：登录成功、退出、打开编辑器时卡片高度一帧变过去，居中的卡片连头部一起跳。
- 还有：头部的 `.thread-account-*` 规则早已没人用（账号入口已经在右侧工具坞里）；裁剪框是圆角方框，头像却是圆的；关闭弹窗后焦点掉到 `<body>`（工具坞在弹窗打开时被卸载，打开它的按钮已经不在了）。

## 二、现在：一列，围绕一个"身份"

`AccountDialog.tsx` 画一列，居中在一个身份上：一个 56px 的圆，没登录时是空的，登录后变成你的头像（没有头像就是首字母）；下面是标题和一行说明。圆下面是一个"视图"：

| 视图 | 圆 | 标题 / 一行 | 下面 |
|---|---|---|---|
| checking | 空圆 + 转动的细弧 | Loom 账号 / 正在确认登录状态… | 无 |
| form | 空圆 | 登录 Loom（或 创建 Loom 账号）/ 用途 | Google、GitHub，"或"，邮箱、密码、（注册时）确认密码，墨色主按钮，"还没有账号？创建账号"，一行安全说明 |
| account | 头像 + 绿点（离线时琥珀色） | 你的名字 / 邮箱 | 一组两行（编辑个人资料、个人主页与使用洞察），"退出登录"和"凭据已安全保存在本机" |
| editor | 头像 + 相机徽标，可点 | 编辑个人资料 / 同步说明 | 头像（移除 / 更换）、昵称（带计数）、取消 / 保存 |
| unconfigured / error | 空圆 | 说明 | 一个次要按钮 |

- **一个命名空间**：卡片里的一切都是 `.acct-*`，只由 `account-auth.css` 定义；别的代码认的三个钩子（`.loom-account-backdrop / -dialog / -close`）保留。门户的同名类不再碰得到它。
- **一个主操作**：主按钮在两个主题里都是墨色（`--pl-ink` 底、卡片色字），没有紫色、渐变和光晕；紫色只表示焦点。次要操作是细线按钮，像链接的操作是字（不吃按下的底色，`data-press="none"`）。
- **字不推表单**：输入框的提示（邮箱不完整、密码规则、两次一致 / 不一致、昵称计数）放在标签那一行的右边，打字时表单不动；邮箱不完整要等离开输入框后才说。
- **细节进提示**：服务地址和完整的安全说明放进说明行的 `title`（应用自己的提示框），界面上只留一句话。
- 快捷登录打开浏览器后，表单上方折出一行"请在浏览器中完成登录…"（一个呼吸的点），登录结果到达就自动变成账号视图。
- 字号只用 12 / 13 / 14 / 18 / 24，字重 500 / 600；宽度所有视图都是 400px。

**裁剪头像**（`AvatarCropDialog.tsx` + `avatar-crop.css`）说同一种话：普通标题和一行说明（去掉图标方块），方形取景里挖出一个圆（圆外压暗，因为头像在别处都显示成圆），三分线去掉；缩放是"− 滑条 +"和百分比，滑条是墨色细轨；"重置"是字，放在左边；"使用头像"是墨色主按钮。操作提示改成取景区的无障碍标签。

## 三、动效（都在 motion-tokens.css 的刻度上）

- **打开 / 关闭**：仍是面板语言的整卡淡入淡出（`.pl-reveal`，文字不位移）。里面身份先到，视图晚一个 stagger（40ms）；圆在 slow 步上用 soft 弹簧从 .92 落定；状态点 / 相机徽标在 pop 弹簧上"出生"。
- **视图切换**：卡片挂在一条线上（`.loom-account-backdrop.pl-scrim { align-items: start }`，两个类是因为 panel-language.css 在后面加载、会把所有 scrim 居中），所以高度变化只动下边缘、头部不动。`useHeightMorph` 用 ResizeObserver 记住画出来的高度，换视图时用 Web Animations 在 flow 步（320ms）和 move 曲线上从旧高度滑到新高度；被打断就从当前画出的位置接着走。文字"淡出再淡入"：旧的在 fast-out（120ms）、exit 曲线上淡出，新的晚 100ms 在 base（240ms）上淡入，两行标题不会叠在一起读；离开的视图绝对定位，不占高度。
- **圆的换脸**：几张脸是不透明的、叠在一起；旧的不动，新的在上面从 .9 放大淡入，所以圆不会中途变暗。
- **视图里出现的东西**（确认密码、错误、离线提示、等待浏览器）用 grid 行折叠在 base 步上让出位置，再淡入；折起时是 `inert`，焦点循环会跳过它。
- **减弱动效**：时间刻度本身收成 1ms，高度直接变，交叉淡入不出现，呼吸的点不再呼吸。

## 四、顺手修的

- "重新检查"按钮的样式；门户样式串门（命名空间）；死掉的 `.thread-account-*` 规则。
- 关闭时卡片继续显示它离开时的视图（原来关闭的那一帧会把编辑器换成账号视图、把表单清空，在淡出的 200ms 里看得见）；临时字段等卡片真正卸载后才清。
- 从个人主页直接打开编辑器时，第一帧就是编辑器（原来先闪一下账号视图）。
- 关闭后焦点回到工具坞的账号按钮：打开它的按钮已被卸载时，按 `data-tool-id` 找它的接班者。
- 换视图后焦点留在卡片里（表单 → 邮箱，编辑器 → 昵称，其余 → 卡片本身）；焦点循环跳过 `tabIndex=-1` 和折起的元素。
- 头像图片画不出来时退回首字母，不显示破图。
- 个人主页头部的头像从 19px 圆角方块改成圆（`profile-insights.css`），和工具坞、账号弹窗、裁剪圆窗一致。

## 五、测试与工具

- `tests/test_account_dialog_contract.py`（7 条，读源码）：一个命名空间、不借门户的类、身份圆的三张脸和不变暗的换脸、挂线 + 高度在刻度上滑动 + 淡出再淡入、提示在标签行 + 折叠、墨色主操作 + 链接不吃按下底色 + 字号不低于 12px、裁剪是圆窗、夹具能扮演账号服务。
- `desktop-react/scripts/tests/account-dialog-browser.mjs`（不进 CI，和别的 browser 测试一样）：两个主题下六种状态都画在卡片里、宽 400、圆角 18、身份居中、主按钮是墨色；登录时逐帧记录：顶部不动（< 0.75px）、高度经过中间值、旧文字淡出；注册折出确认框、Tab 在卡片里循环且不进折起的框、不一致的提示不推动表单；错误；编辑器保存后标题变成新名字；退出后邮箱获得焦点、Esc 关闭后焦点回到工具坞；减弱动效时没有滑动和交叉淡入。用 8 种破坏（居中、去掉滑动、折叠不 inert、紫色主按钮、焦点不归还、减弱动效仍滑动、提示推表单、去掉淡出）逐一验证它会失败。`LOOM_TEST_START_SERVER=1` 时自己起 Vite。
- 夹具 `live-app.tsx` 新增 `?account=in|out|offline|offline-in|unconfigured|error`、`?oauth=0`、`?authLatency=`、`?accountLatency=`：登录（密码 `wrong` 被拒）、注册（`taken…` 邮箱已存在）、快捷登录（稍后自动回调）、保存资料、退出都会改变下一次读到的状态。不带 `?account` 时和原来一样是已登录。
- 拍片的方法（这次用过，放在 `C:/tmp/acct/tools`，不入库）：CDP `Animation.setPlaybackRate(0.1)` 把 CSS 和 Web Animations 放慢，同时把 `window.setTimeout` 拉长同样倍数（presence、Crossfade 的交接、夹具的延迟都跟着慢），连续截图拼成一张接触表。

## 六、没有做的

- 桌面端仍然只有邮箱 + 密码的直接注册（`/auth/register`）；服务端已经支持邮箱验证码注册和找回密码（`emailVerification`、`passwordReset` 都是 true），网页门户也已经有这两个流程，桌面端没有接。这是功能，不是外观，留作后续。
- 网页门户自己的登录弹窗（`portal-auth-dialog.css`，Newsreader 风格）是另一套表面，没有动。
- `header-action-family.css` 里也还有两条 `.thread-account-*` 死规则（不是这次的文件）。
