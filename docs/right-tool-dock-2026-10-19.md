# 右侧工具坞重做（2026-10-19）

起因：用户发来右侧窗口边缘的截图（工具坞和旁边的滚动条），说“帮我优化一下右侧这个区域，尤其美化一下工具坞，包括相关动画和交互效果等，随意发挥”。
这一轮把工具坞（`RightToolDock.tsx` + `right-tool-dock.css`）整个重写：材质不变（一块面、一条发丝线、工作区自己的柔阴影，没有渐变 / 高光 / 模糊），变的是它怎么回应你。

## 旧版的问题（先量、再改）

1. **每个按钮自带一个提示。** 十个隐藏节点；指针从一个按钮移到下一个，上一个淡出、下一个淡入，看上去是两块提示在闪。同时按钮还有 `title`，Electron 约一秒后再弹一个系统提示，叠在自己的上面。
2. **悬停、打开都是按钮自己的底色。** 没有“从这一个移到那一个”的连续感；打开状态只是一层几乎看不出的淡紫，要凑近才分得清哪个面板开着。
3. **排序**走的是 HTML5 拖放：浏览器给一张半透明的拖影，落下之前其他工具一动不动。
   - `Alt+↓` **从来不会移动**：旧 `move(from, to)` 是“插到目标前面”，而向下移时目标正好是下一个，插完等于原地不动（只有 `Alt+↑` 有效，测试也只测了它）。
   - 方向键遇到禁用的按钮就卡住：对 `disabled` 的按钮 `.focus()` 什么都不做，焦点停在原处。
   - 十个按钮是十个 Tab 停靠点。
4. **不可用的工具**（没选项目时的文件夹）只有 `opacity: .35`，原因要悬停等系统 `title`。
5. **出现和离开没有过渡**：设置页盖住应用时坞凭空消失，回来时凭空出现（pop-in 探针会报这一类）。
6. 几何和颜色是手写的：40px 胶囊、30px 按钮、半径 15 / 8、深浅两套各自写死的 rgba。

## 现在

### 几何与材质

- 胶囊 44px = 按钮 32 + 内边距 5×2 + 发丝线 2；**半径同心**：按钮 10 + 内边距 5 + 发丝线 1 = 16。仍在 56px 的轨道里居中（左右各 6px），`--loom-tool-rail-track` 没动，所有面板的 `right` 照旧。
- 每个工具占 34px（按钮 32，上下各 1px 属于槽位，所以指针在两个工具之间永远不在“空气”里）；分隔线 14×1，上下各 4px。
- 所有颜色来自 `--loom-workspace-*`，深浅主题是同一套规则（旧版浅色是另一份 rgba）。图标 16px、线宽 1.75（家族规则）；终端图标 17.5px（光学尺寸：它的提示符和光标只占 24 格里的 16×14，同样大小画出来整列看上去偏轻；用 8 倍截图量过，11 个图标的墨迹包围盒都在各自瓷砖中心 0.1px 以内，只有它偏小）。
- 胶囊是唯一浮在画布上的东西，阴影比面板略深一点（`--dock-shadow`：深色 `0 6px 18px` .2，浅色 .07）；仍然没有渐变、高光、模糊。
- 窗口矮到放不下整条坞（< 470px）时坞自己滚动，滚动条不画；提示挂在坞外面，所以这时也看得到。

### 回应

| 东西 | 做法 |
| --- | --- |
| **滑动高亮 (glider)** | 一块底色在整个坞里只有一份，滑到指针或键盘所在的工具。弹簧：ζ .86、.36s，过冲约 0.5%（第一版 ζ .8 是 1.5%，170px 的行程会冲过去 2.5px，像在晃）。第一次出现时先**停靠**（`data-park` 关掉 transform 过渡、强制回流、再放开），所以它不会从上一次的位置滑过来；按下去时缩到 .93。 |
| **名字 (tip)** | 整个坞一份，挂在坞左边（箭头指着工具）；停住约 360ms 才出现，一旦出现，移到下一个工具时**不再等**（320ms 内关掉再开也算），而且是滑过去的；键盘聚焦立即出现；点击后到指针离开前不再出现（不挡着刚开的面板）。内容：名字、数量、用户在设置里绑的快捷键（设置 `Ctrl + ,`、运行详情 `Ctrl + Shift + I`，按 `normalizeShortcut` 拆成键帽）；不可用的工具写出原因（名字 + 一行说明）。原来的 `title` 去掉了，读屏用 `aria-label` / `aria-description`。 |
| **打开状态** | 淡紫的瓷砖从 .78 弹到 1（弹簧 ζ .52，过冲约 3% 的位移），瓷砖朝面板那一侧有一根 2×14 的竖针；按下时瓷砖缩到 .92。 |
| **点** | 数量只是一个点（7px，数字在名字里），弹入弹出；点周围的“缺口”是它所在位置的底色（悬停 / 打开的瓷砖里挖出来，不是一圈亮边）。账号的绿点同理；头像在时头像是 22px 圆图，绿点压在它的角上。 |
| **工作在跑** | 后台任务有运行中的任务时，数量点到达时扩散两次；终端图标的光标慢慢眨（`data-ic-live`，动作在 `icon-motion.css`，模型一次运行进行时 `html[data-loom-live]` 它静止，和别的装饰一样）。 |
| **出现与离开** | `useMotionPresence(!hidden, 200)`：设置页 / 个人页 / 账号 / Files 盖住应用时坞淡出（180ms），回来时胶囊从边缘滑入 12px，工具依次（22ms 间隔）升起 8px；应用启动同样。 |
| **拖着走** | 指针拖动超过 4px 才算拖：工具被举起（放大 1.07、抬升阴影），经过的工具按**真实距离**（含分隔线那一格）让位，落下时弹簧落入槽位（300ms）。落下的一帧没有跳：先清掉所有让位样式（过渡关掉），同一任务里 `flushSync` 提交新顺序，位置本来就一致。落下后紧跟的那次 click 被吞掉；`Esc` 放回原位（之后松手也不算 click）。 |
| **键盘** | 整个坞**一个 Tab 停靠点**（上次用的那个，禁用了就第一个可用的）；↑↓ 跳过禁用的，Home / End；`Alt+↑/↓` 移动，焦点跟着工具（React 移动节点会让它失焦，布局副作用里还回去），位移用同一根弹簧滑过去（FLIP，减少动态时不播），读屏会听到“X，第 N 位，共 M 位”。旧版 `Alt+↓` 的 no-op 修了（现在按下标移动，不再“插到目标前”）。 |
| **减少动态** | 所有过渡 `none !important`，不做 FLIP，进出场直接到位；功能一样。 |

### 弹簧（`scripts/motion-lab/icon-spring.mjs` 生成）

- glide：ζ .86，.36s（滑动高亮、让位、落下）。`RightToolDock.tsx` 里 `SPRING` 是同一条曲线的副本（键盘重排用 WAAPI 不能读 CSS 变量），改一处要改两处。
- pop：ζ .52，.46s（瓷砖、竖针、点的弹入）。
- ease：ζ .9，.3s（提示的滑动、进场）。

## 踩到的

- 逐帧量出的（`dock-trace.mjs`）：第一版高亮用 ζ .8 的弹簧，170px 的行程在落点后又冲出 2.5px，肉眼是“晃”；换 ζ .86 后 204px 的行程只冲出 0.34px，约 190ms 走完 99%。
- 位置要用**布局像素**（`offsetTop`），不用 `getBoundingClientRect`：后者含进行中的 transform（进场的 `translate`、键盘重排的 FLIP）和 web 版的 CSS zoom。拖动时的让位距离也是布局像素；指针位移除以 `dock 的渲染高度 / offsetHeight`。
- 禁用的按钮不派发鼠标事件，所以**槽位**（包着按钮的 div）听指针，禁用按钮设 `pointer-events: none`。`aria-disabled` 不能替 `disabled`：右侧工具坞测试用 `isDisabled()` 判断“网页版不能假装有浏览器”。
- React 为了重排会移动 DOM 节点，聚焦的节点被移动就失焦：重排后还焦点。
- `:focus-visible` 只在聚焦那一刻读（`onFocus` 里 `matches(":focus-visible")`），鼠标点击聚焦不亮高亮、不弹名字。
- 共享检出：另一个会话在同一批文件里加“任务进度”工具（`17af7b92`），它的提交把我当时没提交的坞重写一起带进去了——不用撤；我之后只提交自己的路径。它的 `task-progress-panel.css` 用了 12.5 / 13.5px 和 13 处低于 11.5px 的字号，`test_design_scale_contract.py` 的两条在 HEAD 上是红的，已经告诉那个会话。

## 没做 / 以后

- **滚动条**：应用里的是 Chromium 原生细滚动条（`styles.css` 的 `* { scrollbar-width: thin; scrollbar-color: ... }`），能改的只有颜色，形状归系统；`customScrollbars.ts` 那套自绘的目前只被两个夹具引用，应用没加载。没动。
- 头像没有时用的是图标，没做首字母。
- “后台任务”面板（`z-index: 2100`）开着时盖住左边的提示。
- 只在无头 Chrome 里跑过，没在 Electron 窗口里实测（150% 缩放的 DPR 1.5 / 2 / 3 截图看过）。
