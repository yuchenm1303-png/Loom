# Loom 仓库代码审计（2026-11-09–10）

结论：本轮发现并修复了一组会破坏停止语义、模型身份、持久化和资源上限的缺陷。不能据此宣布“每一行都最优”。这里区分可复现缺陷、已验证修复与尚未证明的优化，避免用大量改动代替可靠性。

## 范围和方法

边界是 Loom 主仓库受 Git 跟踪的源码；`.cache`、构建产物和有自己 Git 根目录的 `tr-fix-entitlement` 外部仓库不属于本次修改范围。工作区存在其他任务的并发修改，未将其整包纳入本次提交。没有部署、切换用户模型、恢复原研究任务或重启用户的 Host。

盘点时：Agent runtime 153 文件 / 60,722 行，项目与长目标 28 / 7,807，其他 app 102 / 28,038，Electron 102 / 13,533，React/CSS 等前端 399 / 112,998，服务端 24 / 10,325，Android 8 / 1,310；另有测试与脚本。数字为源码盘点，不表示逐行人工阅读全部文件。

采用源码调用链审查、311 个 Python 源文件的 AST 检查、全量测试基线、针对失败边界的真实回归、TypeScript 检查及生产构建。重点阅读请求/回合、队列/恢复、子代理、长目标调度、存储/日志、进程执行、附件和远程控制边界；同时检查网关的鉴权、设备绑定、在途请求上限和超时逻辑。AST 检查未发现语法错误、重复方法定义或列表/字典/集合形式的可变默认参数；这不是完整安全审计或形式化证明。

## 可复现缺陷及修复

| 优先级 | 缺陷 | 最终处理与理由 |
|---|---|---|
| 高 | `_stop` 保留 checker，却没有取消它；暂停/预算耗尽后独立检查仍可能采样 | 取消执行但保留会话和观察；明确恢复后继续同一个 checker，不把人为停止计为检查失败。覆盖暂停、预算耗尽及停止落盘前 Host 丢失的路径。比直接丢弃 checker 重新读文件更节省，也保留证据。 |
| 高 | 子代理 `_run_queued` 吞掉模型准备异常后继续，可能使用默认模型 | 将队列回合准备移入 TurnRunner 的取消/失败边界，在采样、压缩之前运行；模型配置与额度错误形成真实 `turn_failed`，不发出兜底模型请求。队列输入由失败回合持久化接收，避免悬空 Future 或无限重复派发。 |
| 高 | 目标 JSON 读取错误或格式损坏一律变成 `{}`，下一次 put 可覆盖其他目标 | 只把文件不存在视为空；损坏/不可读则拒绝写入，保留原文件。调度器记录存储错误，避免阻断无关项目的 tick。没有自动重置或“修复”用户数据。 |
| 高 | `_settle` 收集报告、usage、diff/check 任一环节报错，就跳过关闭子代理 | 关闭动作放入独立 finally；收集/关闭异常使该线显示失败和原因，不假装正常完成。测试直接注入 journal 错误并确认 close 仍执行。 |
| 高 | 报告阶段发生 provider 错误后转 waiting，再恢复成普通 running；报告宽限和限额可被绕过 | 记录进入等待前的状态；恢复只要求报告，保留 pressedAt，等待期间也检查宽限与 125% 上限。兼容旧记录只有 asked 的情况。 |
| 高 | Office 附件仅限制压缩文件大小；直接解压 XML；XLSX 重复引用共享字符串可在最终截断前构造巨大文本 | 读取前限制 XML 单成员 16 MiB、累计 32 MiB、条目 4096；XLSX 在逐格构建时扣除 2M 字符预算。无需解压的嵌入媒体不计 XML 限额。超限仅跳过自动文本提取，原文件照常保留。 |
| 中 | 附件的 turn_id 前缀直接组成路径，目标父目录还可能指向 workspace 外 | 校验 turn 文件夹字符并检查解析后的目标仍在 workspace 内。不是对任意恶意文件系统竞态的沙箱承诺。 |
| 中 | 远程幂等请求的 action 成功后 deepcopy 抛错，不设置 ready，重复请求可一直等待 | 结果复制纳入异常边界；释放等待者，并保留“写已执行、结果构造失败”的错误记录，避免相同请求再次执行写操作。原先 action 自身抛错的重试语义保持。 |
| 中 | 新增目标行 `li:has(...)` 与手机 `... textarea` 选择器违反已有样式失效约束；450/550 字重违反既有四档预热约定 | 目标行直接由 React 标记可展开状态，输入框用专用 class；标签/强调回归现有 500/600 档，避免额外未预热实例。既有性能约束测试通过，不以删测试掩盖问题。 |
| 中 | 新增面板的 25 处文字低于既有 11.5px 下限；另有 12.5/17px 偏离字号阶梯、执行日志的 11.5px 偏离整数像素约定 | 对照引入字号约束的 `f18b5fb2` 定位新增回退，将这些说明文字提高到既有 11.5px 档，目标标题/操作使用 18/13px，执行日志使用 12px。已提交样式中低于下限的声明从 324 降到 299，保留测试原有 303 上限；历史的低字号仍需按面板逐项评估。 |

另修订五处过期测试约定：流式子输出保留 DOM 身份；输入框增加更新保护属性后仍检验样式和 ref；无时间的研究评测保留其独立条件；打包 renderer 的回退通过 `currentUiDocument` 选择；线程管理能力包含已有的 handoff。评测说明文档同步区分有时间与无时间场景。均保留对实际功能的约束，不修改产品行为迎合旧字符串断言。

### 恢复与验真的边界

模型准备现在在真实回合内运行，因此失败会有新回合、输入和终止事件。没有把配置错误伪造成完成，也没有把日志中没有结果的工具调用重放成成功。准备可能刷新磁盘上的模型元数据，采样前重新载入会话，避免新的平台和旧的模型字段不一致。准备前后都检查取消。

停止 checker 的恢复提示明确说明是暂停/预算停止，不再误称为供应商故障；Host 丢失执行栈时先按现有 `recover_interrupted` 协议使旧执行失效，再唤醒新回合。已有观察仍是历史证据，需要重新观察的状态不能假定仍有效。

## 方案取舍和剩余问题

- 16/32 MiB 的 XML 上限是保护 Host 的保守初值，没有通过用户附件分布证明为最优。大文档仍可附加，自动文本伴随文件可能缺失；PDF 提取仍依赖现有库，尚未变成具有独立内存/CPU 硬上限的工作进程。
- 线程环境变量仍不是 CPU 强配额；脚本可显式覆盖。200k 工作上下文、分线触发阈值和 quota 探测策略需要真实任务的质量/成本数据比较。本次没有随意改小窗口、加闸门或强制分线。
- 目标状态仍跨 JSON 与 SQLite 保存，未改造成单事务。当前修复防止损坏后静默覆盖，不代表突然断电时所有跨库状态都具备一次提交语义。
- 远程幂等记录仍是进程内存，Host 重启后的跨进程幂等和记录容量策略尚需设计。简单 TTL 淘汰可能导致旧写请求重放，因此没有把加 TTL 当作无风险优化。
- 全量测试不能替代真实 Windows 权限、OS sandbox、更新安装、Android 打包和长时间供应商运行验证。本轮没有实际投放研究实验，也不能证明论文新意或研究成果有效。
- 生产 renderer 构建仍提示大 chunk：主 JS 约 2.29 MB（gzip 约 775 KB），主 CSS 约 1.25 MB（gzip 约 292 KB）。需要结合首屏和长会话测量决定拆包，不能仅为消除警告调整阈值。
