# 发送：胶囊被拎起、带过去、放下（2026-10-17）

起因：用户说“需要优化一下消息发送过程动画，从输入框飞到消息界面中保持简约高级即可，一切按你的审美随意设计优化”。
这是胶囊那版（`docs/send-capsule-2026-10-15.md`）的第三遍。落点预测与跟踪、保留真实条目、首页淡出、引导、减少动态、版式交接这些机制都没动；换掉的是**胶囊自己长什么样、怎么落下**，以及两处顺手量到的毛病。
实现仍是 `src/sendFlightMotion.ts`（物理，纯函数）+ `src/sendFlight.ts`（DOM）+ `src/components/send-flight.css`（样子）。

## 一、上一版为什么不够“简约高级”（先拍了基线：暗/亮两套主题 × 单行/折行/首页/引导）

- **外观比它要变成的东西强得多。** 药丸是 7% 紫的底、30% 强调色的描边，下面还托着一团 16% 强调色的辉光（暗色下像一圈紫光）；落地要先变成“亮描边的圆角矩形”，再褪成灰色气泡。中间状态比起点和终点都更显眼，等于每次发送都演一遍“按钮 → 气泡”。
- **落地像撞击。** 压扁（≤7.5%）+ 光环 + 回弹，路径还有 4–5 px 的过冲。算上拉伸、倾斜、起步的鼓起、三段材质，一共 9 个部件同时在动，每个都对，合起来是“热闹”。
- **折行消息（最常见的情形）的版式交接在起飞的前几帧高对比地重影。** 输入框版式和气泡版式两层文字用 68 ms 互补淡化：中间两层各 50%，而且此时胶囊还几乎没动（起步速度低，重影看得最清）；右侧还漏出旧版式的字（`the error m`、`sign-in flo`）。
- **引导（任务运行中发送）的第一帧，输入框的占位符立刻回来**（`::placeholder` 不透明度 1），压在刚飞出的文字下面。老的规则只管“换了输入框”的那种（`.crossfade-in`），引导发送时输入框不换，是 `.crossfade-current`。

## 二、设计：一个“高度”

胶囊是一件被拎起、带过去、放下的东西。**它离开页面有多高（`lift`，0 = 贴在页面上，1 = 在空中）是外观唯一跟随的量**：

- 离开输入框时被拎起：70 ms 内从 0 平滑升到 1（一开始不抖），整体比落地时大 1.4%（≤7 px，文字不跟着放大，所以是药丸在字周围“松”了一点）。
- 阴影就是这个高度：随它升起、随速度向后拖一点、落下时收掉。
- 接近落点时放下：高度随“已经走完的路程比例”下降（60% → 98.5%），所以它**恰好在停下的时候落到页面上**，不早也不晚。
- 材质也是这个高度的函数：暗色下离页面越近越亮（比气泡亮一档的实心药丸），亮色下是纯白 + 阴影；落下时药丸让位给气泡自己的底色（`card`，真实气泡的克隆），描边随药丸一起褪。
- 没有撞击、没有光环、没有辉光、没有第二个效果：一件东西被放下。

### 看到的（单行消息，约 520 px 的路程，暗色）

| 时间 | 发生了什么 |
| --- | --- |
| 0 | 第一帧就是输入框：字在原位，皮肤从这一帧开始长出（28 ms，平滑），阴影随高度升起 |
| 0–80 | 起跳：峰值速度 ~2800 px/s 出现在 74 ms；药丸被拎起（阴影到 100%，整体 +1.4%），倾斜不超过 0.8°、拉长不超过 1.6% |
| 80–200 | 药丸保持完整，走完约 78% 的路程；这一段是“胶囊”本身，没有别的在动 |
| 200–335 | 放下：阴影收、尺寸回落、药丸的圆角和描边让位给气泡的 10 px 圆角和底色（路程 80% → 97.5%，速度从 ~1000 降到 ~100 px/s） |
| 335–458 | 最后不到 3%（≈15 px）慢慢滑进位置；此时已经是气泡的样子，只剩位置在收 |
| 458 | 交接给真实条目：位置差 ≤0.01 px |

总时长 `arrive × 1.16`（上一版 ×1.4）：常见一行 553 → 458 ms，长路程 643 → 532，近的宽气泡 494 → 409，一跳 448 → 371；到位时间 `arrive`（290 + 0.2 × 距离，夹在 320–470）没变，所以“多出来的尾巴”是上一版里那段已经看不出在动的最后几个像素。

### 材质（`send-flight.css`，亮暗各一套）

- 暗色：`color-mix(--loom-workspace-ink 9%, --loom-workspace-canvas)`，比气泡（canvas 上 5.5% 的洗色）亮一档；1 px 描边是 10% 强调色混进 10% 白，只剩一点点紫的光泽；顶上一条 6% 的高光。
- 亮色：`--loom-workspace-panel`（白）+ 9% 强调色混进 9% 墨色的描边；落下时变成气泡的 4% 灰。
- 阴影：一块比胶囊大一圈的椭圆径向渐变（不是模糊的 `box-shadow`），中性色，暗色 .36、亮色 .20；去掉了强调色的辉光和光环。

## 三、怎么做的

### `sendFlightMotion.ts`

`capsuleMotion({ dx, dy, width, height })` 现在返回七个部件的关键帧加一条 `lift`：`path`、`lean`、`shell`、`pop`、`skin`、`card`、`halo`（上一版还有 `settle`、`ring`）。

- **路径**：还是横竖两条弹簧（竖向 0.82×、横向 1.22×，路径是一道弧）；过冲上限 5 → 1.6 px（实际 y ≈1.1，x 为 0：横向弹簧到最后才第一次越线，被收尾包络接住）；峰值速度 2455 → 2803 px/s，提前到 74 ms。
- **`lift`**：`smooth(0, 70 ms, t) × (1 − smooth(0.6, 0.985, 已走路程比例))`。比例是沿“起点→终点”方向的投影，圆弧的横向误差不算。
- **`skin`**：`smooth(0, 28 ms, t) × (1 − smooth(0.8, 0.975, 比例))`；**`card`**：`smooth(0.74, 0.96, 比例)`。药丸是实心的，所以任何时刻 `skin + card ≥ 1`，没有“空心”的瞬间（上一版需要一层“同材质、气泡圆角”的 `settle` 去盖住药丸来避免凹陷；现在气泡的底色是一层很薄的洗色，叠在药丸上不会凹，那一层就不需要了）。
- **`shell`**：大 1.4%（≤7 px）× 随加速度的拉长（≤3.5%，≤9 px，实际 1.6%）；压扁去掉了。**`lean`**：≤1.1°（常见 0.76°），随速度“压进”爬升。
- **`halo`**：不透明度 = `lift`；向速度反方向拖最多 9 px，抬高 7 px。

### `sendFlight.ts`

- 胶囊 = `halo`、`skin`、`card` 三层 + 文字（上一版五层）。会动的层 9 → 7，径向渐变 3 → 1。
- **折行消息的版式交接躲到皮肤后面。** 输入框版式的字（`send-flight-field`）现在是 ghost 的**最底层**（在 shell 之下），胶囊长出来的皮肤是一层面纱：旧版式在 8–18 ms 里从它后面退出，新版式在 8–20 ms 里叠在上面进来（共用 `EASE_CROSS`，不再是 68 ms 的互补淡化）。旧字从不画在皮肤上面，所以右侧也不再漏字。最糟的一帧：两个版式同时各 30%，文字最淡 64%（上一版 50%/50% 持续 4–5 帧）。数字由 `scripts/tests/send-flight.test.mjs` 里一个小模拟钉住，不在测试里重复写常量。
- 胶囊在输入框的字周围的形状（`hug`）和随后长成气泡的缩放/位移（`reshapes`）沿用；`RESHAPE_MS = 120`，缓动改成 `cubic-bezier(.3, 0, .1, 1)`（先快后长缓），因为交接已经在前 20 ms 里完成。

### `send-flight.css`

- 材质见上；`ring`、`settle` 的规则删掉。
- 占位符：`.composer-mode-crossfade[data-sent] > :is(.crossfade-in, .crossfade-current) .composer textarea::placeholder`。引导发送时占位符 230 ms 里不透明度为 0，之后 300 ms 内升回来（文字早已离开）。

## 四、量到的

- 交接：幽灵最后一帧对真实气泡，位置差 0.00 px（实时跟踪两次）；像素差均值 0.60（旧 0.72）、超阈像素 0（旧 41）、最大差 17/765（旧 150）。
- 每个部件起点、终点都在静止：路径起点 = 输入框，终点 = 条目；壳矩阵、倾斜、阴影 = 单位/0；皮肤 = 0、气泡自己的底色 = 1（单元测试对 7 种路程逐一验证）；`lift` 两端为 0。
- 3000 条随机路程（0–700 px 级、宽高随机）：`lift` 在 [0,1]、只升一次只降一次，皮肤只降、气泡底色只升，`skin + card` 不低于 1，过冲 ≤1.2 px，峰值速度 ≤4330 px/s，没有 NaN。
- **首次发送的 GPU 开销**（全新配置、无着色器缓存、5 轮交替，Chrome trace 里发送后一秒内的忙碌时间，中位数）：GPU 主线程 542 → 427 ms，池线程（着色器编译）390 → 250 ms，渲染主线程 314 → 255 ms。第二次发送相同（599 → 524 / 178 → 212 / 876 → 869）。headless、噪声大，只说方向，不是受控基准；少了两层和两个渐变是它变轻的原因，不是单独做的优化。
- 引导发送时占位符的不透明度（每帧采样）：旧版第一帧起就是 1，新版 0 持续 ~230 ms，再升回 1。

## 六、没做、可以做

- 输入框一侧的反应（退一下、顶边亮一下）：仍然没做，理由同上一版——每次发送多一个动效。
- 折行文字的**逐词/逐行重排**（FLIP）：版式交接现在是“躲在面纱后面的一帧左右的溶解”，已经不再重影，但字还是“换了”而不是“流过去”；逐词做需要 N 个合成层和每词测量，对富文本（代码块、列表）又要另想，首次发送的 GPU 开销会反过来变重，没做。
- 发送失败时飞回输入框（上一版就留着的）。
- 有头 Chrome 抓真实合成帧：这台机器上窗口被节流，验证仍是冻结 + 跳帧（它说的是动画“说了什么”，不是显示器“画了什么”）。

## 七、坑

- 冻结跳帧的 film 看不到 `::placeholder`（它的动画不在 `document.getAnimations()` 里）：要看占位符，就在页面里每帧采样 `getComputedStyle(textarea, "::placeholder").opacity`（`scripts/tests/send-flight-browser.mjs` 场景 6）。
- 引导发送第一帧“字叠字”是真的，不是工具假象（旧版同样）：输入框是同一个，没有 `.crossfade-in`，占位符直接回来了。
- `git ls-files --eol`：这些文件索引里是 LF、工作区是 CRLF（`core.autocrlf=true`）；从镜像拷回来的 LF 文件要转成 CRLF 再看 diff，否则每个文件都是整文件改动的样子。`git show HEAD:path | grep -c $'\r'` 会骗人（按工作区习惯输出），用 `git cat-file -p` / `git ls-files --eol`。
- 另一个会话占着端口 5196：镜像的 Vite 起在 5187，`cacheDir` 指到镜像自己的目录（不要共用 `node_modules/.vite`）；镜像里 `node_modules` 是联接，删镜像前先 `cmd /c rmdir` 联接。
- 冷启动的 Vite 第一次 `page.goto` 超 30 s：先用 `curl` 把 `live-app.html` 和 `live-app.tsx` 各取一遍。
- 在别人也在改的工作区里，动画这种要反复看的改动放镜像里做（改坏、调参、拍帧都在镜像），定稿再拷回主树，一次提交；半成品留在共享树里会被别的会话 `git add -A` 带走（见 `shared-checkout-sweep-commits`）。
