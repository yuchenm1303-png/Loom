# 长目标的章程、笔记与审稿式评审（2026-11-08）

## 为什么

人说"你有一整晚，做出真正属于这个领域的成果"，期待的是一份完整的、行家级的成品。原来的长目标是"一句目标 + 一直做 +
核对是否完成"，时间剩得多就把检查者想到的"加深"清单钉上去再做一轮。真实的一晚（`E:\ai run`）交回的是一堆实验，
没有主线；加深在使用者看来"像是做完了又被强行拉回去"。

调研过的系统（Sakana AI Scientist v2、Agent Laboratory、港大 AI-Researcher、Kosmos、Google co-scientist、
Anthropic 长时间运行 agent 的做法）形状一致：先把请求展开成交付物和固定的验收清单，按阶段推进，靠评审和修改变深；
最常见的失败是编造数字、自以为新、实验代码跑不通。目标是向顶尖研究的标准靠拢来打磨体验，不是真的去发论文。

## 做了什么（`app/project_runner/goal_charter.py`）

- **章程**（`weave_charter`）：交付物（顶尖行家会交出的东西）、3–24 条可检查的验收标准、2–10 个阶段、类别。
  长目标开始后、会改东西的操作之前要写好（读文件不挡；最多挡两次就放行）。修改要写理由；被删的标准保留为 dropped，
  再列出就恢复。`weave_goal` 的回复带着写章程的指引（研究：先查文献和新意，试点两三个方向再选定，说明理由）。
- **笔记**（`weave_note`）：做了什么、发现了什么（带数字）、决定了什么、下一步；每个目标轮带最近 6 条，最多存 60 条。
  审稿意见的逐条回复也写在这里。
- **审稿式评审**：检查者按章程逐条判定（`criteria: [{id, met, evidence}]`），并按行家标准列 major / minor；
  不能复现的数字、找不到的引用算问题。打回时把未达标的标准、major、minor 一起交回，要求逐条回复。
  通过且时间还多时，它提出的改进写进章程成为"第 N 轮修改"的新标准和新阶段（取代钉上去的加深）；
  下一轮评审拿到上一轮的意见和之后的笔记，检查是否真的改了。没有章程的旧目标照旧把改进要求以文字交回。
- **界面**：建造页和手机在长目标下面显示交付物、当前阶段、评审轮次和每条标准（已达标 / 未达标 / 待完成 / 已放弃）。
