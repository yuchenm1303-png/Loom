## 修复的预算与连续性缺陷

1. **内置模型默认工作目标。** 官方直连 MiniMax M3 / 已声明的 DeepSeek 型号只带已知窗口，不再额外默认附加 128k 工作目标。显式保存或通过环境配置的工作目标仍然有效；代理和未知型号不凭名称取得官方容量。
2. **触发阈值与摘要输入分离。** 软工作目标决定何时压缩和替换历史的大小，不再限制摘要能读取的原始历史。摘要请求受已声明或可信供应商拒绝所证明的容量约束；未知容量不使用工作目标或默认计量窗口冒充供应商上限。
3. **格式重试保留证据。** 空摘要、错误语言或意外工具调用不是容量不足的证据。此类重试读取相同历史；只有实际容量约束或供应商上下文长度拒绝才按完整工具协议单元裁减摘要输入。
4. **落盘与请求预算一致。** 检查点落盘、恢复引用插入复用请求预算的供应商 token 校准和容量判定。删除落盘时额外的“压缩线八折”裁剪；未知容量不因检查点落盘变成已知容量。
5. **最新用户指令优先。** 可选恢复引用放不下时保留原来的有效替换历史，不能为了引用挤掉最后一条用户指令。完整历史仍在检查点归档中。
6. **换模型隔离计量。** 根据模型请求快照记录的 `profile_id / provider / model` 隔离估算校准、最近供应商使用量和容量拒绝记录。任务历史继续共享，计量不从另一模型继承。没有可归属身份的旧计量记录不能证明当前模型的容量。

请求元数据增加 `compaction_trigger_tokens` 与 `compaction_trigger_usage_tokens`，检查点后预算记录显示实际解析的输入上限和校准样本，便于复验触发原因。

## Codex 源码依据与策略边界

对照本地公开 Codex 源码 `a7660cd15490875b8c22f66e577da115ed927fe3`：

- `codex-rs/protocol/src/openai_models.rs` 的 `ModelInfo::auto_compact_token_limit` 将窗口的 90% 作为默认阈值，显式阈值也不能超过该值；有效窗口另行约束。
- `codex-rs/core/src/session/context_window.rs` 区分活动窗口使用量与总窗口边界。
- `codex-rs/core/src/session/turn.rs` 在请求准备和工具执行后的安全边界检查自动压缩，而不是等待供应商拒绝所有请求。

Loom 的已声明 512k 窗口因此默认采用 460,800 token 的触发线。输出预留、实际请求硬容量、供应商拒绝或显式工作目标仍可能使压缩更早发生。这是可解释的默认策略，不是所有模型都已通过真实质量测试的“最优值”。摘要本身有损；检查点归档、真实用户消息、计划和可读取的工具证据负责恢复精确细节。
