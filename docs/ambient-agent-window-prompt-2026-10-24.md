# 交给另一个窗口：Loom 轻量常驻助理

你在 C:\Users\邹羽宸\Loom 工作。请研究并实现 Loom 的「轻量常驻助理」能力。另一个窗口正在设计重型长期项目执行，两者要共用后台运行底座，但本任务不实现大型项目拆分、多 agent 开发调度、自动合并或长期项目验收。

## 用户要的结果

Loom 后台可以持续在线，关闭聊天窗口后仍可等待消息、事件、到期任务；有事才调用现有 agent runtime，处理完回到等待。空闲不调用模型、不消耗模型 token。定时巡检若调用模型，要明确计入用量。不要把常驻实现为不断向模型发送「继续」。不需要每个周期向用户汇报；只在有意义的变化、完成、失败或需要用户处理时通知。

1. 阅读实际 AGENTS.md、现有 Host/Desktop/App Server 生命周期、durable goals/queues、会话锁、用量统计、权限与恢复代码。工作区有其他窗口未提交改动，保留它们，只提交本任务文件。
2. 查阅 OpenClaw 当前官方 Gateway/Automations 文档和相关源码，核实当前版本，不照抄过时 Heartbeat 配置。补查 Hermes 的 scheduler/gateway，区分已经验证的能力和自己的设计。
3. 先写简短设计和模块边界，再完成实现与验证。现有能力能复用就复用，避免再造模型/工具执行循环。

## 必须完成的能力

- 后台执行所有权与窗口解耦；检查现有 bootstrap/Host 能否承载，只有生命周期不足时再提取服务。启动、退出、重启、单实例、状态查询均有明确语义。
- 本地持久化触发器：一次性定时、周期定时，以及一个真实可验证的本地事件源。外部消息平台做可扩展适配接口；没有凭证不伪称接通，也不要擅自新增账号或付费服务。
- 事件去重、合并、忙时排队、每会话单执行者、重启后任务核对、失败退避。区分漏过的周期与需要补跑的任务，避免开机后成百上千次补跑。
- 用户可查看、创建、修改、禁用、删除任务，暂停常驻和停止正在执行的任务。用户取消不能被下一次自动唤醒立即撤销。
- 调用现有 runtime 时保留原有权限与凭证边界；保存触发来源、执行关联、结果和用量。重启不恢复旧审批凭证，不盲目重放结果未知的外部操作。
- 默认监听、计时和健康检查用普通代码；仅有需要判断的变化时调用模型。所有自动调用都能被用户查看并设限。
- 通知持久化并去重；无通知路由时仍保留本地结果，不伪称已发送。未经用户授权不发送外部邮件或消息。
- 提供清晰、符合现有界面的最小可用入口，用户能看出后台是否在线、下次触发、上次结果、是否等待审批。

## 与重型项目模式的接口约定（设计候选，需核实实际代码）

提供可复用的 Host 生命周期、执行准入/取消、持久事件投递、资源租约、用量记录、结果通知接口。轻量模块只负责事件/时间触发，不自行接管长期项目状态机，不因一个会话 turn 完成就把长期项目判为完成。重型项目的自动恢复由项目调度器决定，不能把所有中断会话无差别续跑。接口和所有权写入文档，避免两个窗口修改同一核心模块产生双重调度。

## 验收

用可重复的测试和真实短时间运行证明：空闲不调用模型；到期任务恰当入队；重复事件只生成一次逻辑运行；繁忙时正确排队；关闭 UI 后仍能执行；服务重启后定时任务保留且不重复副作用；取消/禁用后不意外重启；审批等待不会被自动绕过。说明 Windows 注销、锁屏、睡眠和重启对不同工具能力的实际限制，不宣称睡眠期间还能运行。
